## Project vs Framework Boundary (`contract.ts` & `cookie-main.ts`)

- **`src/contract.ts` stays 100% project-level:** It owns Warm Batch domain configuration (`CAST` element names, `FLAVORS` copy/pricing/tints, `STAGE_SIZE`, `LENS`, `JAR_METRICS`). Moving site vocabulary or flavor tables into Gerak packages would introduce project coupling and a house look (explicitly excluded by `ARCHITECTURE.md` §6).
- **`@gerak/core` stays strictly pure:** Neither `contract.ts` nor `cookie-main.ts` belongs in `@gerak/core`. Core owns pure time, curves, signals, 3D math, and state folds — zero `window`, DOM, `ResizeObserver`, or Three.js types.
- **`src/cookie-main.ts` splits between project wiring and `G-07` renderer helpers:** Three.js studio construction (`world-studio.ts`), `.glb` assembly (`world-models.ts`), and page startup stay per-project, while only the two generic Gerak integration seams (`window.__motionReady` typing/registration in `@gerak/dom` and `binder.resize` synchronization in `@gerak/dom` + `@gerak/three`) warrant small framework helpers (`G-07`).

## Sequencing Decision

Finish **Sections 1–5 on `feat/cookie-piece`** first within current Gerak while documenting concrete friction here. Once the full 5-section site proves the exact shapes needed, consolidate **`G-05` + `G-02` + `G-01` (+ `G-03a`/`G-07`)** into one clean Gerak ADR and implementation PR rather than designing prematurely from Phase 0 alone.

## Verified in Phase 0

- `GLTFLoader` + `window.__motionReady` + Google Fonts (`Fraunces` & `Plus Jakarta Sans`, `display=swap`) passed headless `gerak measure`, `gerak review`, and Chromium frame captures across desktop (`1440x900`) and mobile (`390x844`) with `pageErrors: []`.
- `mount` + `threeBinder(studio.world, { objects, draw })` binds `jarRoot`, `jarLid`, and `cookieHero` cleanly alongside DOM `data-cast` elements on a single `"live"` clock.
- `applyPose3d(camera, LENS)` keeps the Three.js `PerspectiveCamera` locked to the exported `LENS` so `travel({ to: slotHeroJar })` aligns 3D framing with responsive CSS slots.
- Parent-child hierarchy (`jarRoot` -> `jarModel` -> `jarLid`, `cookieHero`, and the contact `ShadowMaterial` plane) lets `travel` and `responsiveJarScale` move and scale the jar assembly together without slicing the jar base across responsive viewports.

## Verified in Section 1

- `heroCopy` and `offerSeal` compile with `drive.kind === "scroll"` for Chromium `ScrollTimeline` compositor offload while `jarUnseal` and `cookieLift` run smoothly on 3D spring-damped scroll beats.
- Sticky `.hero-stage` pinning (`overflow-x: clip`, `.hero-sticky { min-height: 100vh }`) works seamlessly with `travel({ to: slotHeroJar })`, `heroCta` hover lid peek (`watch: true`), and `pointer.x`/`pointer.y` parallax on desktop (`1440x900`) and mobile (`390x844`).
