# Warm Batch — Gerak Friction & Gap Log

Tracks genuine authoring friction discovered while building `apps/pieces/cookie/` on `feat/authored-cast`.

| ID | Phase | Area | Friction / Missing Primitive | Workaround | Proposed Gerak Capability |
| --- | --- | --- | --- | --- | --- |
| `G-01` | Phase 0 | Scene composition | Single-owner element rule refuses referencing the same 3D object (`jarRoot`, `cookieHero`) across separate section scenes merged via `.include()`. | Keep shared 3D objects declared in one owning module or compose their multi-section motion chain in one builder while keeping section DOM scenes modular. | Allow `.include()` or a declarative multi-beat binder to attach non-overlapping beat motions to a shared persistent `object` across section modules. |
| `G-02` | Phase 0 | 3D `travel({ to: slot })` | `travel` on `object` ignores `fit`, `arc`, and `.take()`, and requires a fixed camera `lens` with `Object3D` resting at world origin. Confirmed on mobile `390x844`, where an unscaled jar overflowed `slotHeroJar` and overlapped the hero CTA row. | Center the jar visual mesh inside `jarRoot` at `-height * 0.57` so origin aligns with slot center; compute `responsiveJarScale(context)` manually from `LENS.fov` and `rest` boxes; keep camera fixed on `LENS`. | Support optional `arc` (world-space lift), `fit` (depth-aware framing scale), and `.take()` transitions on 3D `travel` motions. |
| `G-03` | Phase 0 | 3D `object` options | `object(name, { view })` does not support `watch: true` (pointer raycasting) or `parts: true` (instanced/repeated 3D parts such as 6 stacked cookies). | Use DOM hit-target slots (`box(..., { watch: true })`) for pointer interaction and register individual `object` entries for each animated 3D cookie. | Add optional `parts: true` for homogeneous 3D object lists and optional raycasted `watch: true` pointer events on `threeBinder`. |
| `G-04` | Phase 0 | `@gerak/rapier` 3D | Rapier 3D wrapper supports only `sphere` and `box` colliders and exposes no dynamic body removal/reset for interactive jar-builder edits. | Approximate jar walls with box colliders or drive cookie drops with deterministic Gerak curves/arcs when users add or remove flavors. | Add `cylinder` collider shapes and body add/remove/reset helpers in `@gerak/rapier` for interactive 3D packing scenes. |
| `G-05` | Phase 0 | 3D `travel` clock parity | Unwindowed `travel({ to: slot })` sits on the slot from `0ms` on a `"live"` mount, but sweeps across the full scene length on a `"timed"` clock — causing `gerak review <scene.ts>` to fail with `"jarRoot is still moving on the last frame"`. | Wrap `travel({ to: slotHeroJar })` in `.in(jarSettle, ease.cubicOut)` so both `"live"` mount and `"timed"` review share an explicit settle window before the final hold. | Give `travel` an option (or slot-hold semantics) to rest on its target across timed scenes too without drifting or violating final-hold checks. |

## Verified in Phase 0

- `GLTFLoader` + `window.__motionReady` + Google Fonts (`Fraunces` & `Plus Jakarta Sans`, `display=swap`) passed headless `gerak measure`, `gerak review`, and Chromium frame captures across desktop (`1440x900`) and mobile (`390x844`) with `pageErrors: []`.
- `mount` + `threeBinder(studio.world, { objects, draw })` binds `jarRoot`, `jarLid`, and `cookieHero` cleanly alongside DOM `data-cast` elements on a single `"live"` clock.
- `applyPose3d(camera, LENS)` keeps the Three.js `PerspectiveCamera` locked to the exported `LENS` so `travel({ to: slotHeroJar })` aligns 3D framing with responsive CSS slots.
- Parent-child hierarchy (`jarRoot` -> `jarModel` -> `jarLid`, `cookieHero`, and the contact `ShadowMaterial` plane) lets `travel` and `responsiveJarScale` move and scale the jar assembly together without slicing the jar base across responsive viewports.
