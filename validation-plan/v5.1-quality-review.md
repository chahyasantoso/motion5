**Review date:** 2026-11-02

**Gate:** `npm run check` — `scan:raw-templates`, `scan:comments`, `format:check`, `typecheck`, `test` all `PASS`

## 1. Verdict

The v5.1 direction is sound: commit-time self-validation, branded structures, nominal typed slots,
pure 2D/3D domains, and the single live-write guard are the right shape. The initial implementation
was green but had five correctness/invariant gaps, including two reproducible runtime defects.

All findings below are fixed. The tree now has targeted regression tests for the two defects that
were reproduced with probes.

---

## 2. Fixed Findings

### B1 — Authored typed edits were not transactional

**Was:** Value planning validated the schema but not the data-type `parse`; the runtime adopted the
new authored entry before `ValueTrack.replaceValues` parsed the structure. A domain refusal threw
after adoption, leaving the authored definition and compiled track disagreeing.

**Fix:**
- `validateAuthoredValues` now runs `parseDataType(type, authoringValue(values), ...)` during value
  planning, so a domain-invalid edit is refused before staging.
- `ProjectRuntime.#adoptValueChange` now rewrites the compiled track before writing the authored
  entry; a rewrite failure leaves both untouched.
- `project-runtime.ts` now passes `capabilities.dataType` into structural track validation.

**Regression tests:**
- `packages/core/test/unit/contract/data-type.test.ts` — “refuses a domain-invalid authored edit
  before adopting it”.
- The existing cycle/range cases now fail at plan time.

### B2 — Computed typed structures were cached forever

**Was:** `PluginTrack.#computedStructure` cached by `sourceId + type.id` and never invalidated. A
valid authored row-set change in a producer made a dependent `fk`/`fk3d` fail with
`Solved row set changed after commit.`

**Fix:**
- The cache now stores `{ structure, signature }`.
- `structureSignature` hashes table row ids plus static cells (and record static fields).
- A changed signature reparses the structure; an unchanged signature returns the cached value.

**Regression test:**
- `packages/plugins/test/integration/fk-aggregate.test.ts` — “AK-12a refreshes a computed solved
  structure when the producer row set changes”.

### B3 — Plugin output contract had no enforcement

**Was:** `PluginDefinition.outputs` was not tied to the `transform` return type, and S5 removed the
runtime output validator. Malformed output sets could publish and fail at a consumer.

**Fix:**
- First-publish validation is restored as exactly one check per compiled track:
  `PluginTrack.#outputsChecked` gates `validatePluginOutputs`.
- The check enforces declared outputs, required/optional presence, reserved names, value shape, and
  row-id uniqueness, then freezes the result.
- Later frames trust the accepted set; the steady-state frame path remains free of output
  validation.

**Regression test:**
- `packages/core/test/integration/identified-plugin-runtime.test.ts` — “refuses a malformed first
  output set”.

**Residual:** this is a first-publish boundary check, not a compile-time output-shape type. A
generic output-shape parameter on `PluginDefinition` would be the full compile-time fix; it was not
introduced because it would require a broader public type migration.

### B4 — `bindGoals` accepted extra or duplicate rows

**Was:** `bindGoals` indexed by value row id and never compared `byId.size` with the value length or
the committed structure length. An extra goal row was silently dropped.

**Fix:**
- Rejects duplicate value row ids.
- Rejects an extra/unknown row set before binding.
- `bindBody` and `bindSolved` already enforced the same invariant.

**Regression test:**
- `packages/plugins/test/unit/goals/domain.test.ts` — extra row and duplicate id cases.

### B5 — Frame-time validation remained

**Was:** `PluginTrack.compose` ran `validateRuntimeValue` on local values, the optional
`plugin.validate` hook, `isValue`, and output-presence scans every frame. Engine also ran
`checkSources` at commit and `PluginTrack` repeated it on first compose.

**Fix:**
- Removed the composed-time local `validateRuntimeValue` call. Authored values are validated at parse,
  commit, and value-plan time; live overlays are validated by `planWriteLive`.
- Removed the `plugin.validate` hook from `PluginDefinition`, catalog admission, and
  `PluginTrack`. `checkSources` is now the only plugin-provided cross-source check.
- Added interpolation-boundary clamping: `createValueEvaluator` accepts the value spec and clamps
  animated numeric cells to their `FieldSpec.min`/`max` after the interpolator. Values are no longer
  periodically revalidated to catch easing overshoot.
- Engine passes the authoring spec into `ValueTrack`; `PluginTrack` passes the plugin local value
  spec into its evaluator.
- `PluginTrack.markSourcesChecked` seeds the commit-time `checkSources` verdict, so the first frame
  does not repeat it. `checkSources` still reruns when a structure signature changes.
- Removed the `plugin-validation-warning` rule; `plugin-validation-failed` remains for
  `checkSources` failures.

**Regression tests:**
- `packages/core/test/unit/runtime/evaluate-values.test.ts` — “clamps an interpolated numeric cell
  to its declared bounds”.
- Existing live-value and composition tests were updated to remove the retired `validate` hook.

**Residual:** `pickOutputs` and `isValue` remain as cheap shape/presence narrowing guards, not full
`ValueSpec` validation. `GraphPublisher.validateComposition` still performs its renderer-neutral
boundary walk; this is the host publication boundary, not plugin domain validation.

### M1 — Legacy aggregate reader was a second owner

**Was:** `src/aggregate-topology.ts` still owned a duplicate topology parser, and production
`fk`/`fk3d` imported `POSE_*_SPEC` from it.

**Fix:**
- Moved the legacy reader to `packages/plugins/test/support/aggregate-topology.ts`; no production
  module imports it.
- Added `packages/plugins/src/pose/fields.ts` as the production owner of pose specs.
- Updated `fk`, `fk3d`, `packages/three`, and all tests to import production specs from their
  domain/pose modules.

**Verification:** grep finds no `aggregate-topology` import under `packages/plugins/src`,
`packages/three/src`, or `apps`.

### M2 — Dotted typed slot names lost structures

**Was:** `PluginTrack` derived the structure map key from the last path segment, so a typed slot
named `data.points` stored under `points`; `checkSources` then skipped the required structure.

**Fix:** the slot/member key is passed explicitly into `#resolveSlot`.

**Regression test:**
- `packages/core/test/unit/contract/data-type.test.ts` — “keys a dotted typed slot's structure by
  the full slot name”.

### M3 — 3D twist inversion was accepted

**Was:** `BodyError` range inversion checked only `minRotation`/`maxRotation`; `minTwist` above
`maxTwist` passed commit.

**Fix:** `invertedRanges` checks both rotation and twist pairs; the error carries the bound kind and
the type adapter reports it.

**Regression test:**
- `packages/plugins/test/unit/body/domain.test.ts` — inverted 3D twist bounds.

### M4 — Structural typed validation omitted `dataType`

**Was:** `ProjectRuntime.#acceptTrack` and the structural plan validator passed only
`isPluginRegistered`, so typed add/replace could skip type/spec checks until compile.

**Fix:** both contexts now pass `capabilities.dataType`.

**Regression test:**
- `packages/core/test/unit/contract/data-type.test.ts` — typed track added through the structural
  tier with an unknown type is refused.

### M5 — `assertStable` ignored numeric static cells

**Was:** `staticSignature` skipped every numeric cell, so numeric static fields could move
undetected.

**Fix:** `StabilityOptions.staticFields` declares numeric fields that must remain constant; those
are compared. Non-static numeric animation remains intentionally ignored.

**Regression test:**
- `packages/plugins/test/unit/testing/assert-stable.test.ts` — declared numeric static field.

### L1 — Admitted DataType objects were mutable and identity-deduped

**Fix:** `readDataType` now freezes the admitted type and its spec before registration.

**Residual:** nested maps inside `spec` are not deep-frozen; the type contract itself is frozen.

### L2 — Dead surface

**Fix:** removed unused `genericDataType`; removed `plugin.validate` and its warning rule; output
validation is live again as the first-publish boundary. `plugin-validation-failed` remains a real
producer through `checkSources`.

## 3. Residuals and Design Notes

1. **First-publish output validation, not compile-time output typing.** B3 is closed behaviorally,
   but `PluginDefinition` still accepts a broad `Outputs` return. A future generic
   `PluginDefinition<Input, Specs>` would move the check to `tsc`.
2. **Cheap narrowing guards remain.** `pickOutputs` and `isValue` do not walk a `ValueSpec`; they
   only protect the boundary from a producer that violates its declared contract. They are not
   counted as domain validation.
3. **Host publication boundary.** `GraphPublisher.validateComposition` still walks outputs for
   renderer neutrality. D10 permits a publish-boundary check; it is outside the typed-slot domain
   path.
4. **`assertStable` static fields are caller-declared.** This avoids guessing staticness from a
   plugin output shape; callers should pass the fields owned by their data type.
5. **Process:** S2 and S3 were committed together because `solved2d` registration is supplied by
   `fk`’s typed slot; the slice boundary in the plan could not stand alone. The final tooling
   commit also carried the repository-wide Prettier pass.

## 5. Remaining Test Gaps

- No direct test that a steady-state frame performs zero `DataType.parse`, `checkSources`, or
  `validatePluginOutputs` calls. The implementation is structured for it; a spy-based invariant test
  should be added before release if that guarantee is contractual.
- No test for a typed map slot with empty members or a computed map structure.
- `assertStable` does not inspect record output key changes; it compares table row ids and static
  cells. Extend when record producers use the helper.
