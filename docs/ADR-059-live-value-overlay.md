# ADR-059: One live value overlay in Track, two entry points in ProjectRuntime

**Status:** Accepted, 2026-08-30

**Context.** `TrackHandle.replace(next)` validates a whole `TrackDefinition`, stages a replacement Track, rebuilds the graph, and handles transactional rollback. That is the right cost for a topology change and the wrong cost for moving one number. `Track#setProgress` already had the cheap shape: write the interpolator, mark dirty, let the caller invalidate. There was no value equivalent, so an editor that wanted to drag a bone length had to recompile the node.

The issue's original wording needed tightening in one place. `Track` retains no authored-values object to merge into: values come from `#timeline.state` through `interpolated()`. And the interpolator's `state` is a live foreign object, the same mutable record a GSAP tween writes into every tick, so writing a value into it would be a second authored channel hidden inside the adapter's own scratch space, torn by the next `progress()` call and invisible to `handle.track`.

**Decision.** One immutable `#values` overlay in `Track`, applied inside `interpolated()` after renderer-neutral filtering and before any plugin runs. That one read is what ordinary composition, `composeFrom`, and the publisher's `MemberState` all go through, so a masked value cannot reach one of them and miss another.

Two entry points in `ProjectRuntime`, and they differ in exactly one thing:

- `overrideValues(nodeId, values)` masks the live Track and leaves the retained definition alone.
- `setValues(nodeId, values)` masks the live Track and writes a fresh frozen `TrackDefinition` into the `#tracks` entry, so `handle.track` and the composition cannot disagree.

Both go through one private write path whose only per-entry-point parameter is what the retained definition becomes. Neither validates a definition, stages a Track, or calls `replaceGraph`. Both end at `this.#graph.invalidate([nodeId])` and record diagnostics exactly as `seek()` does, so there is one invalidation owner and one diagnostics channel.

**The mask is derived from the retained definition rather than accumulated across calls.** Every static authored leaf is masked with exactly what the definition says it is, and the keys a caller named are the only ones that differ. That is what makes agreement structural rather than careful: an override cannot outlive the authored value it masked, a `setValues` cannot lose the value an earlier one wrote, and `overrideValues({})` is a clear back to authored truth rather than a hole. It also means a mask is replaced wholesale by the next live write, whichever entry point makes it.

**Key validation is the two owners that already existed.** A key is legal if it is present in `ResolvedPlugins.authoredKeyframes`, the flattened authored record, and if `readAuthoredLeaf` says its leaf is not animated. That collapses five of the issue's rejection cases into one table: an unknown key, a key another plugin owns, a namespaced `:` key, and an interpolator scratch `_` key are all simply absent, because ownership was settled at resolve time and neither reserved spelling can be authored. `Track` holds no `PluginRegistry` and reimplements no ownership predicate. The refusal is `LiveValueKeyError`, rule id `live-value-key`, carrying the node id, the key, and one reason.

**An animated key is refused, by name, and `patchKey` is not added.** The `Interpolator` port has no per-key member at all, so adding one means a new `InterpolationTimeline` method, two GSAP implementations, the fake in `testing/`, and a contract tier for a capability with one consumer. That is a second slice with its own invariant. A partial implementation that permanently froze an authored animation is the failure this refusal exists to prevent, so it is tested as the contract rather than as a gap, and `LV-12` asserts the port grew no member.

**This is not a second input channel.** The overlay is this track's own pre-plugin value domain, exactly as `composeFrom`'s seed is. No authored form populates it, nothing outside the runtime holds a value to put in it that did not come from an author, and a value bound from another node still reaches a plugin only through its declared slot. [ADR-047](./ADR-047-observes-output-only.md)'s invariant is about where an _upstream_ value may land, and it holds unchanged: `requirementInputs` is still the only parameter one can arrive by.

**Alternatives rejected.** Writing into `#timeline.state` gives the adapter's scratch object a second meaning and loses the value on the next tick. Two layers inside `Track`, one for an override and one for an authored replacement, would make the domain layer the owner of a distinction only the definition owner can enforce, and would put the same merge in two places. Exporting the registry's private `claims(plugin, key)` predicate would hand `Track` the weakest half of the ownership answer and make it a second owner of key ownership. A `clearOverrides()` member, or an `overrideValues(null)` overload, would be a second mechanism answering the one question "what masks the interpolated values"; an empty record already is no mask, on the precedent that an empty authored array is an accepted leaf that compiles to nothing.

**One deviation from the implementation plan, stated rather than discovered.** The plan called for two `ProjectRuntimeOptions` hooks, `overrideValues` and `setValues`. There is one. `Track` holds a single mask, so a second hook could only point at the same method, and two hooks for one mechanism is two owners of one question. What separates the two entry points is the definition rewrite, which never leaves `ProjectRuntime`.

**Consequences.** `Track.interpolated()` gains a layer every existing caller reads through, so `publisher-solver-members` and the `track-compose-from` cases are the regression surface that matters most. The public surface gains two `TrackHandle` members, two `ProjectRuntime` methods, one `ProjectRuntimeOptions` hook, one error type, and the `LiveValues` type the members take; `LiveValueKeyError` and `LiveValues` cross the package entry for the reason `StaleTrackHandleError` does, and `Track` itself stays private. Nothing in `graph/`, `contract/validate-v5`, `adapters/`, or the plugins is touched. A mask is dropped by `replace()` by construction, because that stages a freshly compiled Track and disposes the displaced one.

**Evidence.** `LV-1` through `LV-14`, across `unit/domain/track-live-values.test.ts`, `unit/runtime/live-value-updates.test.ts`, and `integration/live-value-composition.test.ts`. The failing-first run is `33310177625`, archived on the `ci-logs` branch at `logs/33310177625/`: fourteen failures, seven hundred and fifty-two passes, and both `typecheck` and `format:check` green before them, because the not-yet-existing seam was declared locally in each red file and cast rather than named. `LV-3` is the load-bearing one: a member's `length` reaches an IK solve only through the publisher's `MemberState`, so a mask that did not land in `interpolated()` cannot move a published rotation at all.

**Sequencing.** Lands after [ADR-056](./ADR-056-uniform-stale-track-handle.md). Both new members route through the same `#liveEntry` resolver and refuse a stale handle with `StaleTrackHandleError`, and `SH-1` covers them from its own surface derivation rather than through a private copy of that contract.
