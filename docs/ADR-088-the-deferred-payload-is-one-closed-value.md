# ADR-088: The deferred payload is one closed value, and a host cannot reroute a runtime failure

**Status:** Accepted, 2026-09-16

**Context.** Five findings from second quality pass over runtime publication seam, read at `ab9d3df56c60570c6629f60d6a4bc08360171327`: [#392](https://github.com/chahyasantoso/motion5/issues/392), [#393](https://github.com/chahyasantoso/motion5/issues/393), [#396](https://github.com/chahyasantoso/motion5/issues/396), [#400](https://github.com/chahyasantoso/motion5/issues/400) and [#401](https://github.com/chahyasantoso/motion5/issues/401). Four share one shape: value nearly discriminated union, question answered beside it not by it. ADR-083 made lifecycle + snapshot memo one value each, left deferred payload interface with two fields; ADR-084 put frame inside that interface, never revisited what liveness means. Fifth, [#400](https://github.com/chahyasantoso/motion5/issues/400), same defect one layer out: act with five callers, no owner.

**Decision one. `PendingPublication` is a closed branded union rather than an interface with two fields.** Nothing pending is variant, not empty instance of other. That answers [#396](https://github.com/chahyasantoso/motion5/issues/396) structurally: `NOTHING_PENDING` cast live `Set` through `ReadonlySet`; constant shared by every runtime in process → one caller reaching that object + mutating it corrupted all. Freezing set or copying on access both keep collection and price mistake; variant holds no collection → nothing to hand out, nothing to freeze. Cast deleted, not made safe. `deferredSeeds` sole reader of deferral's own set, answers copy → no set leaves module by any path.

Union branded exactly as other two, for reason [#387](https://github.com/chahyasantoso/motion5/issues/387) gave: variant declaring only its discriminant is not closed — TypeScript's excess-property check reads fresh object literal, not value arriving through variable → payload stating frame beside no deferral assignable through one intermediate `const`.

**Decision two. A deferral is pending exactly when it exists, and a frame is work by itself.** [#392](https://github.com/chahyasantoso/motion5/issues/392): `isPending` read seed count → reentrant `flushAtTick([], tick)` stored frame, booked drain, answered deferred batch, then drain returned immediately: job spent on nothing, frame stranded until later publication cleared payload. Issue offers two answers; tier already chose one in prose: `flush` contract says empty seed list is not cheap flush — derives snapshot, moves sequence, notifies every batch subscriber. So frame is work, `isPending` reads discriminant, drain replays frame-only payload through `flushAtTick`. Dropping frame in `deferring` instead would make docblock + code disagree other direction.

**Refined by [ADR-097](./ADR-097-a-rule-id-is-a-closed-union.md), 2026-09-19.** Two things this paragraph settles were still answered from request, not payload; quality pass over [#449](https://github.com/chahyasantoso/motion5/issues/449) found both. Frame-only deferral answers deferred batch, which this decision already states, and briefly answered empty one, because reason chosen from request's own seed list once both deferred reasons required non-empty one. Reentrant call deferring neither seed nor frame booked drain though nothing pending — never asked for here, and decision two's sentence refuses it: booking is claim drain has work. Both read from `deferredWork` now; frame-only answer reports under `reentrant-flush-deferred-frame`, because seed-carrying rule owns its ids always and frame is not a node to name.

**Decision three. A publication takes the seeds and retains a frame it did not reach.** Half decision two creates rather than closes, decided here not discovered later. Once frame is pending work, live `flush` clearing whole payload would drop it: `flush` has no parameter to reach frame and must not acquire one — ADR-082 made that separation structural. `retaining` answers what publication leaves behind: frame not reached, nothing else; `finally` that already books drain for pending work books one for it. Frame publication did reach is nothing to carry — ordinary case of drain replaying own deferral.

**Decision four. A failed publication re-queues onto a live runtime only.** [#401](https://github.com/chahyasantoso/motion5/issues/401), option 1, for reason issue gives. [#378](https://github.com/chahyasantoso/motion5/issues/378) correctly moved snapshot derivation inside boundary that re-queues drained seeds; derivation runs constructor-supplied `compose` + `interpolated`. Caller code may dispose runtime then throw; `catch` then put seeds back onto object whose phase is terminal, whose drain `bookingDrain` declines forever → carried work nothing would ever publish for life of object. `requeuing` asks phase first. ADR-083's claim: `disposed` carries nothing; payload is field beside phase, not member → this guard says for payload what phase says for itself.

Option 2, folding payload into phase so combination unrepresentable, shape to prefer if payload ever moves for another reason; recorded here, not taken: would make `graph-runtime-state.ts` own publication as well as lifecycle, and boundary between two worth more right now than one fewer guard. Option 3, refusing disposal from inside derivation, refused on sight because [#388](https://github.com/chahyasantoso/motion5/issues/388) deliberately pinned that legal.

**Decision five. Building a diagnostic and handing it to a host is one owner with one boundary, and a host failure is swallowed.** [#400](https://github.com/chahyasantoso/motion5/issues/400), option 1, which issue prefers and calls DRY answer. `#report` ended at `this.#onFlushError?.(diagnostic)`, host code with no boundary of its own → throwing sink left through whichever of five members reporting. `#releaseBooking` where mattered: runs after deferred payload taken, before publication boundary that would put it back → port whose `cancel` throws plus host whose `onFlushError` throws dropped drained seeds outright. [#378](https://github.com/chahyasantoso/motion5/issues/378) fixed that shape one statement further down; same hole survived one statement further up. `diagnostic-report.ts` owns rendering error + handing diagnostic over; one `try` there closes it for all five callers rather than four fixed by narrower change.

Host failure swallowed, not aggregated; record says so plainly because issue asks. Diagnostic answered to caller + retained as `lastFlushError` before sink touched → nothing runtime knew lost. Second diagnostic about sink that just threw would go to that same sink → loop, not report. ADR-039's clock boundaries precedent: failure in injected code labelled + contained where it happens; does not become failure of operation already in flight.

**Refined by [ADR-091](./ADR-091-retention-precedes-handover.md), 2026-09-16.** Two sentences above described implementation repo did not have. Retention did not precede sink: assignment from boundary's return value afterwards — [#415](https://github.com/chahyasantoso/motion5/issues/415). Swallowing host failure lost it rather than containing it — [#410](https://github.com/chahyasantoso/motion5/issues/410). Kept: refusal to hand second diagnostic to sink that just threw; changed: boundary returns nothing, retained slots only answer.

**Decision six. A terminal runtime reports nothing new.** [#393](https://github.com/chahyasantoso/motion5/issues/393). `dispose` releases booking before phase goes terminal → ordinary disposal still reports port that refuses to cancel; existing case pinning that stays green. Refused: reentrant case — handler for one failure retires runtime, failure still unwinding files diagnostic against object that stopped being able to act on one → reader handed two claims contradicting each other. Guard is one line in `#report`, the one owner, not one per rule id.

Scope consequence stated, not found later. Drain failure discovered after caller retired runtime not reported either: report would land on retired object. Honest reading of `disposed` carries nothing; same trade ADR-083 already made for booking + mid-flush phase: terminal runtime stops answering rather than answering carefully.

**Superseded as to retention by [ADR-091](./ADR-091-retention-precedes-handover.md), 2026-09-16.** The paragraph above is kept as the decision this record made, and [#409](https://github.com/chahyasantoso/motion5/issues/409) is that it decided two things at once. Delivery to a host is still refused once the phase is terminal, so the sentence holds for what a host receives; retention is no longer refused with it, so the sentence no longer holds for what the runtime keeps.

**Consequences.** No public export, diagnostic id or rule id moves; `GraphRuntime` remains unexported from `packages/core/src/index.ts` → `describeError` + `reportDiagnostic` internal, emitted declaration closure unchanged. `describe` moves out of `graph-runtime.ts`, not copied → file further under 30,000 byte sister-doc trigger, not across it. `graph-runtime-state.ts` gains four exported answers; `GraphRuntime` gains no branch of own for either question. Both halves of that sentence belong to this record's slice + superseded by refinement above: module gained fifth answer, `deferredWork`; `GraphRuntime.#deferIfFlushing` reads it in exhaustive switch deciding batch + booking together. First sentence superseded with them: one rule id does move, `reentrant-flush-deferred-frame`, for reason refinement gives. `deferred-payload.test.ts` behavioural evidence, every case red before change; state-space cases in `graph-runtime-state.test.ts` red for same reasons one layer down.

**Alternatives refused.** Freezing shared empty set: refused — keeps collection whose only purpose was empty; frozen `Set` still answers `add` by throwing, not by being impossible to reach. Copying pending set on every access: refused, same reason at cost. Making `isPending` conjunction over seed count + frame: refused — two fields answering one question produced #392; discriminant answers once. Guarding re-queue inside `GraphRuntime` rather than state module: refused — phase + payload are that module's to relate. Wrapping every `#report` call site in own `try`: refused as five owners of one question, the ADR-076 defect. Reporting host sink failure through same sink: refused as loop.
