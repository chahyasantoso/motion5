# ADR-083: One lifecycle value, and a memo that carries its whole key

**Status:** Accepted, 2026-09-16

**Context.** [Issue #376](https://github.com/chahyasantoso/motion5/issues/376) reads `GraphRuntime` at `e4d2be0d611ebfbfe86132d7e46d2473c2a456a6`, which is main after [#375](https://github.com/chahyasantoso/motion5/pull/375), and finds two state machines encoded as six independent fields. The lifecycle is `#disposed`, `#flushing` and `#scheduledDrain`: three booleans, eight combinations, two of which mean nothing, each written in more than one place, so the lifecycle is a property a reader reconstructs from the writes rather than a value the class holds. The snapshot memo is `#snapshot`, `#snapshotGraph` and `#snapshotMembers` with `-1` standing in for cold, and `replaceGraph` clears two of those three and leaves the membership revision behind. This is the deferred half of [#374](https://github.com/chahyasantoso/motion5/issues/374), which ADR-082 recorded as owed to its own slice rather than declined, because it is a second invariant with a second blast radius and landing it on top of thirty-three moving call sites would have made one review that could not separate a rename from a rewrite.

**Decision one. The lifecycle is one discriminated value, and `disposed` carries nothing.** `#phase: RuntimePhase` replaces the three booleans. Every transition is one assignment, `#assertLive`, `#deferIfFlushing`, `#onTick` and `#flushTick` each read one discriminant instead of a field, and the two combinations that meant nothing are gone rather than avoided: a disposed runtime cannot be mid-flush, and it cannot owe the scheduler a drain. The second of those was previously kept unreached by a hand-written `this.#scheduledDrain = false` inside `dispose()`, which is exactly the difference this record is about. Unreached is a property of today's call graph. Unrepresentable is a property of the type.

**Decision two. The memo is one value carrying its whole key.** `#memo: SnapshotMemo` replaces the other three fields. Cold is a discriminant rather than a sentinel, so no number stands in for absence and `-1` is deleted. `warmMemo` requires the snapshot, the graph identity and the membership revision together, so a warm memo cannot exist without the whole key it is read by, and `replaceGraph` and `dispose` each assign `COLD_MEMO` where they used to clear two fields of three. The half-cleared key was harmless at that head only because warmth also required the value beside it, so the stale revision was never read; a memo whose key can be half-cleared is the shape ADR-058 refuses one layer up, and it is refused here for the same reason rather than because it had already cost something.

**Decision three, which #376 left open. A booked drain is a field of the live phases, not a phase beside them.** The sketch in #376 and in ADR-082's alternatives offers `draining` as a fourth `kind`, and the issue asks for that case to be decided explicitly rather than inherited. It is refused as written, and the reason is measured rather than aesthetic: a booking is made inside `#deferIfFlushing`, which runs only while subscribers are being notified, so a runtime that is flushing **and** already owes a drain is the ordinary reentrant case, and it is the case `scheduler-reentrancy` drives from the outside. A fourth `kind` beside `flushing` cannot hold that pair, so it would either lose the coalescing that case measures or need a boolean beside it, which is the defect this record exists to retire. So `idle` and `flushing` each carry `drain: "unbooked" | "booked"`, `disposed` carries nothing, and the reachable state space is five values in which all four live combinations are real: quiet, deferral pending, publishing, and publishing with a deferral already pending.

```ts
type RuntimePhase =
  | { readonly kind: "idle"; readonly drain: DrainBooking }
  | { readonly kind: "flushing"; readonly drain: DrainBooking }
  | { readonly kind: "disposed" };
```

**Why `sequence` is not in the phase.** The sketch puts it inside the `flushing` member. It is refused: `sequence` is a public monotonic read that has to answer between flushes as readily as during one, so a copy inside the phase would be a second owner of one question and the getter would have to reconcile them. ADR-076 names that as the defect this project cares about most, and one field that only ever increases is not a state machine. `#lastTick`, `#membersRevision` and `#lastFlushError` stay their own fields for the same reason, and `pendingSeeds`, `tick`, `sequence` and `lastFlushError` all answer exactly what they answered before.

**Why the states live in their own module.** `runtime/graph-runtime-state.ts` owns what a legal state **is**: the two unions, their interned values, and total transitions over them. `GraphRuntime` owns **when** a transition happens. That is one owner each rather than two owners of one question, and it buys the thing the issue asks for and a boolean pair could not give: the four live phase values are not exported, so they are reachable only through `beginFlush`, `endFlush`, `bookingDrain` and `unbookDrain`, and no second place can invent a combination. It is also what makes failing-first evidence possible at all, which is the next paragraph. Interning the values keeps a transition a lookup rather than an allocation, so steady-state ticking allocates nothing here, as optimisation 7c of issue #223 intended for the memo.

**What the evidence can and cannot be.** Neither illegal combination was reachable before this change, so no behavioural case can go red on either one. `dispose` cleared the drain flag by hand, and memo warmth required the value beside the key. A case asserting on what the class does would therefore have been green before and after and would have proved nothing, and a case asserting on the names of private fields would have pinned the spelling of this fix rather than its invariant, which is what #376's acceptance means by evidence that pins the invariant and not the field names. So the evidence is the state space itself, in `packages/core/test/unit/runtime/graph-runtime-state.test.ts`, red at `397bbe0e2dc9d13631309a884d87f7536791e68a` for the honest reason that the module it imports does not exist there: the set reachable under every transition is exactly five values and closed, disposal is terminal under all four, a booking survives the flush it was made inside, a second booking for one drain is refused, and a memo answers only for its whole key. Three `@ts-expect-error` arrows carry the compile-time half in the shape `membership-gating` used for #374, since a disposed phase has no `drain` to read, a cold memo has no `snapshot` to read, and `warmMemo` cannot be called with half a key. One behavioural case is deliberately green on both sides, and it is the regression that keeps this record honest.

**What the blast radius says, measured rather than feared.** Every ordering the booleans had is preserved, and preserved by placing the same writes at the same positions rather than by reasoning about where they could move. `#flushSeeds` releases the booking, derives the snapshot, moves `#sequence` and opens the flush in that order, and closes it in a `finally` whose first statement is total, so a subscriber that disposed the runtime mid-flush leaves it disposed rather than idle. `#drainScheduled` releases the booking before it asks about disposal, which is the order the inline job had and is load-bearing in both directions: releasing first is what lets the flush it runs book its own follow-up, and asking after is what stops a job the scheduler accepted before `dispose` from publishing over a retired registry. `#scheduleDrain` still spells `flush([])` for the reason ADR-082 gives. `scheduler-reentrancy`, `publisher-reentrancy`, `clock-tick-identity` and `publisher-snapshot-memo` are untouched, which is the acceptance criterion #376 states from the other side: if a phase refactor had needed one of them edited, that would have been evidence it changed behaviour rather than evidence it worked.

**One case worth naming, and deliberately not fixed here.** `#flushSeeds` releases the booking on every publication, including one no drain scheduled, so a direct `flush` between a booking and the scheduler running it leaves a job outstanding while the phase says none is booked, and the next deferral books a second. Both jobs are harmless, since the second finds `#pendingSeeds` empty and returns. It is a real disagreement between the booking and the scheduler that holds it, it is older than this slice, and repairing it would move behaviour `scheduler-reentrancy` measures. It gets its own issue rather than a quiet correction inside a refactor whose whole claim is that nothing observable moved.

**Consequences.** No public surface, no behaviour, no diagnostic and no rule id. `GraphRuntime` is still not exported from `packages/core/src/index.ts` and neither is the new module, so nothing in `apps/` or `packages/react` can reach either. Every diagnostic id, rule id and message survives byte-for-byte, `#report` still reads `#members` for each one, and every publication happens for the same seeds at the same sequence as before. Six fields are deleted and two are added. `#scheduleDrain`'s scheduler job becomes a named private, `#drainScheduled`, which is a name rather than a mechanism: the closure it replaces did the same three things in the same order.

**Where the reasoning lives.** `graph-runtime.ts` was 19,528 bytes at `e4d2be0d` and is 23,138 bytes formatted at `b70f10ea95dce777ffe5f6c603ec464c1a75539f`, measured rather than estimated, so it stays under the 30,000 that would oblige a sister document and its members keep their reasoning in source docblocks where the citations stay legal. #376 asked for that number specifically. `graph-runtime-state.ts` is 7,141 bytes and carries its own. ADR-058, ADR-076, ADR-080, ADR-081 and ADR-082 are deliberately not edited: this project supersedes a record with a record rather than amending a decided one, so ADR-082's "deferred" status is answered here and its text stays as it was written, exactly as ADR-082 did to ADR-081's decision two.

**The status file, and why it is in this slice.** [Issue #384](https://github.com/chahyasantoso/motion5/issues/384) found `docs/SESSION-STATUS.md` at 7,960 bytes against a ceiling of 8,000, and found the ceiling already shaping edits rather than bounding them: #375 could not name the follow-up issue carrying this slice, because the link cost about fifty bytes and forty were left. That makes #384 the precondition for this slice's own status rewrite rather than a second invariant beside it, which is why they land together, and #384 names `#376` as the entry the file owes. The trim is the one that issue recommends: the `#362` bullet stops enumerating seven merged phases and their evidence ids, the `57,567`-to-`47,208` arithmetic goes back to #363 and #364 which own it, and "Just landed and exercised" goes entirely now that #336, #337 and #338 are all merged. The file is 7,175 bytes after it, so headroom is 825 rather than 40. `CEILING` is not raised, for the reason the test's own comment gives and #384 repeats: the number is not the problem, and a status file edited under a budget it can breach in one honest sentence gets edited to satisfy the budget instead of to state the status.

**Alternatives refused.** Implementing the sketch literally with a fourth `draining` phase, refused as decision three: it cannot represent a booking made during a flush, which is the case `scheduler-reentrancy` drives. Keeping `#scheduledDrain` as a boolean beside a three-member union, refused because it is the same defect one field smaller and `disposed` beside a booking would still be writable. Putting `sequence` in the `flushing` member, refused above. Defining both unions inside `graph-runtime.ts`, refused because the four live values would then either be exported for the evidence to reach, which lets a second place invent a combination, or be unreachable by any test at all, which leaves the invariant asserted only by the code that has it. Fixing the outstanding-job case named above, refused as a behaviour change inside a slice that claims none. Raising the status ceiling, refused as #384 recommends.
