# gerak documentation

This directory is the project's working contract. It answers questions that should not be rediscovered in every
session.

## Using gerak

To make motion rather than build the runtime, read the [user guide](./guide/README.md). It documents the declared
package entrypoints and nothing else. Everything else in this directory is written for implementors.

## Current reality

Start with [SESSION-STATUS.md](./SESSION-STATUS.md). It is the only document allowed to claim what has landed, and it
states current state only. Do not restate its claims anywhere else: a second copy of the state is a second owner of it.
The standing rules a change is held to are in [../AGENTS.md](../AGENTS.md), one line each.

## Owners and code

- [ARCHITECTURE.md](./ARCHITECTURE.md): the one invariant, the layers, and who owns what.
- [MAP.md](./MAP.md): generated one-line owner per source folder, with each package's public entries.

## Decisions

Every record is its own `ADR-nnn-title.md` file in this directory, and a number names exactly one file.
[ADR-INDEX.md](./ADR-INDEX.md) lists every record with its number, title, recorded status and supersession; it is
generated by `npm run adr-index`, and `adr-integrity.test.ts` refuses a stale one.

Records are history and are never edited; a later record supersedes an earlier one. Before introducing a flag, alias,
facade, second owner, compatibility path or new public export, search them. If the proposal conflicts with an accepted
record, either reject it or add a superseding record in the same pull request.

Many records, and the documents some of them link to, describe the JSON engine that ADR-170 retired. Those documents
carry a line saying so and are kept only so the records still resolve; the code is on the branch
`archive/core-plugins`.

## Delivery

- [PR-WORKFLOW.md](./PR-WORKFLOW.md): branches, commits, pull request contents, review, merge and the status
  discipline every change owes.
- [CI-WORKFLOW.md](./CI-WORKFLOW.md): what each gate runs, and the formatter's pinned settings.
- [TESTING-STRATEGY.md](./TESTING-STRATEGY.md): determinism, source-text claims and what a test may not be.

## Documentation rules

1. Reality belongs in one status file, and that file states current state only. A rule that outlives the change which
   earned it belongs in AGENTS.md, and a change's run ids belong in its pull request.
2. Intent documents label themselves as intent when code does not exist yet.
3. Every new public behaviour needs its reference entry and a test in the same pull request.
4. A decision reversal supersedes the original record in a new one; contradictory records are not left active.
5. Delete documents that describe deleted code in the same change that deletes the code, unless a record links to
   them; then they keep a retired line at the top.
6. A document that a consumer reads belongs in `guide/`, and it may only name a symbol or subpath the package declares.
