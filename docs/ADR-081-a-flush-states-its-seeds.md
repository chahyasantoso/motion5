# ADR-081: A flush states its seeds, and `invalidate` keeps the tick out of the project tier

**Status:** Accepted, 2026-09-14

**Context.** A follow-up on [issue #371](https://github.com/chahyasantoso/motion5/issues/371#issuecomment-5662796600) made two findings about `GraphRuntime`, both accurate as observations, read here at `a44ba132e8211880c198ebf3bdb88bbd05f97ce9`, which is [#372](https://github.com/chahyasantoso/motion5/pull/372)'s green head. First, `invalidate(seeds)` is `this.#assertLive(); return this.flush(seeds);` while `flush` asserts the same condition as its own first statement, so the wrapper's assertion is a second copy of one rule with nothing in between that could change the answer; the class is not exported from `packages/core/src/index.ts`, and `ProjectRuntime.#invalidateSeeds` is its only caller in `src`. Second, `flush(seeds = [...this.#members], tick?)` defaults an omitted argument to a full graph recompute, the most expensive answer the method has, while both internal callers already state their lists: `#flushTick` spells `[...this.#members]` and `#scheduleDrain` spells `[]`.

**The premise about cost is wrong, and this repository is what says so.** The follow-up proposes defaulting to `[]` as the safe and cheap fallback for an unthinking call. At this tier an empty list is not cheap: `flush([])` derives the snapshot, moves `#sequence`, raises `#flushing` and calls the publisher. `LIVE-EDIT-COST.md` has said so for several slices, and ADR-080 records the same sentence from the caller's side one pull request down. What survives is the half that never mentioned cost: a default is the answer an unthinking call gets, so it may not be the worst case the method has.

**The default also had seven dependents, and the measurement excluded all of them.** Checking every real call site excluding tests is true, and the parenthesis carries the finding. Repository-wide, `flush()` with no argument occurs seven times: three in `membership-gating.test.ts`, in a case named for the default and asserting that `flush().seeds` equals the member set, and four in `cross-motion.test.ts`, using the default as publish everything now.

**Decision one. `seeds` becomes required rather than differently defaulted.** Replacing one default with another silently rewrites the meaning of every call that omitted it, which is the failure mode the finding objects to, applied to its own fix. There were seven such calls and one of them asserted the old meaning. Removing the default makes all seven compile errors instead, which is loud, enumerable and impossible to miss. Nothing loses an ability: the only caller that wants every member is inside the class, where `#members` is reachable, and no external caller could express that through the default without already knowing the ids.

**Decision two. `invalidate` keeps its declaration and loses its liveness assertion.** The deletion the follow-up proposes is refused. `invalidate` is `flush` with the second parameter removed, and that parameter is the clock's: `flush(seeds, tick)` moves `#lastTick` and refuses a non-monotonic value, and `invalidate(seeds)` cannot reach it. The project tier must never consume a frame number the clock will reuse on its next frame, and today nothing has to remember that, because the verb it holds has no such parameter. Letting `#invalidateSeeds` call `this.#graph.flush(nodeIds)` would widen what the project tier can reach while claiming to narrow this class's surface. One fewer member and one more parameter in reach of the caller that must not use it is not a simplification, and it is the same argument decision one makes: neither the expensive answer nor the clock-owning one may be reached by omission or by convenience.

What ships from that finding is the redundant assertion, deleted. A disposed runtime still answers `GraphRuntime is disposed.` from `flush`'s own first statement, which is what makes the deletion a deduplication rather than a hole.

**Consequences.** No public surface and no behaviour. `GraphRuntime` reaches no consumer in `apps/` or `packages/react`, no exported type, member, refusal, diagnostic or rule id moves, and every `src` caller already stated its seeds. One compile-time contract changes, and its seven dependents are rewritten in the same slice: each list is the member insertion order the default derived, so what publishes does not move. `membership-gating` stops reading the member set back out of `batch.seeds` and reads the gate from the clock instead, which is where the gate turned out to be, and that correction earns its own paragraph.

**Where membership gates, measured rather than assumed.** `GraphPublisher.flush` publishes every node its seeds reach and consults `snapshot.members` at exactly one place, to decide whether to pull an unpublished upstream source into the affected set. Publication itself is not member-filtered, and `beginBatch` is handed the caller's seed list unchanged. So membership gates the seed list rather than the publication, and `flush`'s member-set default was that gate for any caller who named none. The first draft of this slice's test asserted the opposite, that a named non-member publishes nothing, and CI said otherwise at `59c9243738b97c102c35f7e6829fdc94df6986e0`, one failed case in 1,228. None of the decisions above move: the tick path still seeds `[...this.#members]`, so what publishes on a tick is what it always was. What changes is that the gate now has exactly one reader, the clock's path, where before it could also be reached by omitting an argument. A gate reachable by saying nothing is a gate no reader can locate, which is the same defect decision one is about, found one layer down. `#flushTick` stays the only place that spells `[...this.#members]`, and `#scheduleDrain` the only place that spells `flush([])`. `ProjectRuntime.#publishSeeds` still owns what an empty seed list means, one tier up and untouched by this record.

`GraphRuntime.prototype.flush.length` is the evidence, red at 0 before and green at 2 after, because `Function.length` counts the parameters before the first one carrying a default. A `@ts-expect-error` over an uninvoked `runtime.flush()` pins the same contract at compile time, and a disposal case asserts that `invalidate` still refuses a disposed runtime after its own assertion is gone.

**Alternatives refused.** Defaulting to `[]`, refused above as a silent rewrite justified by a cost claim this project contradicts in two places. Deleting `invalidate`, refused above on the segregation, and separately expensive: it has nine call sites in three unit test files, `LV-5` spies on it by name to assert one publication per live value write, and a spy repointed at `flush` would also see the tick path and the drain, so the claim it makes would weaken rather than move. Making `flush` private so `invalidate` is the sole public entry, which is the cleanest shape on paper: refused because `scheduler-reentrancy` drives `runtime.flush(["hero/arm"], 1)` directly to exercise a synchronous scheduler failure at a stated tick, so a private `#flush` would delete a test's access to the tick seam rather than segregate it. That is a larger redesign than one default is worth and can be reconsidered when something else needs it. A `GUARDRAILS.md` bullet about dangerous defaults: one slice does not earn a standing rule.
