# ADR-084: A deferred publication carries its whole payload, and a booking is a claim about the scheduler

**Status:** Accepted, 2026-09-16

**Context.** Five findings from quality passes over [#375](https://github.com/chahyasantoso/motion5/pull/375) and [#386](https://github.com/chahyasantoso/motion5/pull/386), read at `1af7580557b0ad65a44c4216a0fde7170f33e203` and `d69b38415299822bb2ccdd085941c23aeaa27310`. One slice: one seam, five sides — what a reentrant call leaves behind, who owns it after. [Issue #380](https://github.com/chahyasantoso/motion5/issues/380): payload, was half a payload. [Issue #389](https://github.com/chahyasantoso/motion5/issues/389): booking, claim about wrong thing. [Issue #382](https://github.com/chahyasantoso/motion5/issues/382): precondition guarding publication both feed. [Issue #387](https://github.com/chahyasantoso/motion5/issues/387): gap between ADR-083's state-union claims and type enforcement. [Issue #388](https://github.com/chahyasantoso/motion5/issues/388): one ordering ADR-083 calls load-bearing, no test drove. None introduced by #375 or #386; both refactors made them legible by naming transitions — outcome those slices were for.

**Decision one. Frame number travels with deferred seeds; publication that runs records it.** `#deferIfFlushing` queued seeds, dropped tick — drain publishes through `flush([])`, verb with no tick parameter. Deferred `flushAtTick` kept work, lost frame it was asked to reach; `#lastTick` stayed put for a frame runtime had been told about. #380 offers three answers; this is second: pending state grows frame number, drain replays through `flushAtTick` when carrying one. First answer, refusing deferral for clock verb, refused below — drops work. Third, declaring loss as contract, refused: frame number asked for, silently discarded, not contract but unobserved behaviour with a docblock.

```ts
export interface PendingPublication {
  readonly seeds: ReadonlySet<string>;
  readonly tick: number | undefined;
}
```

**Rule #380 asks for, two deferred frames inside one flush: later wins.** Frame number only advances → replaying earlier refused by `#assertTick`, guard deferral preserves rather than works around. Deferral naming no frame, i.e. every `flush`, leaves pending frame alone rather than erasing it: `flush` cannot name a frame, must not answer for one. Hence `#deferIfFlushing` tick optional, not required. Optionality belongs to the two verbs, one with no frame to hand over; not caller choice: `flush` call site says nothing, `flushAtTick` states its own. ADR-082 retired an operation selected by argument presence on public surface; untouched here.

**Why a pending frame cannot be overtaken.** Worry: pending frame a later publication passed → `#assertTick` would refuse it, stranding seeds behind it. Cannot happen; reason worth writing down rather than guarding: only writer of `#lastTick` is `#advanceTick`, only caller `flushAtTick` on path that goes on to call `#flushSeeds`, and `#flushSeeds` takes pending payload first act. Any publication moving `#lastTick` past a pending frame also consumes payload holding it. Hence no staleness branch in `#drainScheduled` — unreachable branch is a claim asserted only by code that has it.

**Decision two. Validity before reentrancy; recording separate.** `flushAtTick` calls `#assertTick` before `#deferIfFlushing` → frame runtime could never reach refused whether or not publication open. Without it, reentrant call could queue non-finite or regressive frame failing later, inside scheduler job, reported as `flush-failure` under rule naming wrong thing. `#assertTick` owns validity; `#advanceTick` one write to `#lastTick`. Same question twice, one owner: delegation, not duplication. ADR-076 covers two owners of one question, not one owner answering twice.

**Decision three. Booking is a claim about scheduler; publication consuming a drain cancels job it consumed.** `#flushSeeds` released booking on every publication, including one no drain scheduled, while `Cancel` handle `Scheduler.schedule` answers with was discarded. Direct `flush` between booking and scheduler running it took pending seeds, lowered booking, left job outstanding; phase then said nothing booked → next deferral booked second job for one drain. #389 names two ways out; this is first: `Scheduler` port answers with handle carrying `cancel` → booking and handle held together, released together, by one member `#releaseBooking`. Second way, booking a claim about phase only, accepting redundant job, refused: runtime whose own state is wrong about outside world is the defect this project cares about most, one field larger.

`scheduler-reentrancy` coalescing case is #389's oracle, does not move: one booking still one job — coalescing never wrong. What moves: count of _outstanding_ jobs across a publication, two per drain → one. `dispose` cancels for same reason, before phase goes terminal. `#drainScheduled` keeps refusal on discriminant: port may decline to cancel; job that runs anyway must still find retired runtime that says no.

**Why phase lowered before port touched.** `#releaseBooking` assigns `unbookDrain(this.#phase)`, then calls `handle.cancel()` inside boundary. Throwing `cancel` out of contract, but alternative order would leave runtime believing it owes a drain nothing will run — wedge, not diagnostic. Failure reported under `scheduler-failure`, rule already owning scheduler trouble; not swallowed, no rule id of its own.

**Decision four. Both state unions branded → illegal combinations unassignable, not merely unreached.** ADR-083 decisions one and two: combinations six retired booleans could spell are unrepresentable. #387: claim stronger than types made it — excess-property checking reads fresh object literal, not value arriving through variable, so disposed phase carrying a booking, and cold memo still carrying membership revision `replaceGraph` left behind, both assignable through one intermediate const. Nothing observable at risk: both fields private, four live phase values interned and unexported, module not re-exported from `packages/core/src/index.ts`, every write through transition. Matters anyway: moving invariant from call graph into type was whole point of that slice, and "unreached" is weaker property its own decision one argues against.

Two `unique symbol` marks, declared, never exported, sit on variants; `mintPhase` and `mintMemo` only expressions asserting them. No other module can name key → none can spell phase or memo at all, answering #387's wider question about who may construct one. Brands phantom: nothing assigned at runtime, interned values byte-identical, transition still lookup, not allocation.

**Why brand, not optional `never` exclusion.** #387 offers both. Exclusion such as `readonly drain?: never` on `DisposedPhase` closes assignment, opens something else: `drain` then exists on every union member → reading `phase.drain` off un-narrowed `RuntimePhase` legal, existing compile-time case forbidding it no longer a diagnostic. One arrow traded for another; unused `@ts-expect-error` is itself an error → exclusion deletes evidence to add evidence. Brand keeps both: property absent from variant not carrying it; variant closed to anything this module did not mint.

**Decision five. Precondition asserted, not stated.** `#flushSeeds` owned publication mechanics for both verbs, stated one precondition in prose, on argument that second copy of decided question is second owner. Ownership argument sound, kept; #382 corrects conflation. Assertion is not second owner of decision, it is check that decision held. First statement in member, before pending payload taken, before booking released, before `#sequence` moves — being wrong later means violation detected after state it needed thrown away: mutated state, misattributed error, worst shape a precondition failure has.

Unreachable today; one branch is what that costs. `graph-publisher.ts` carries several guards of exactly this kind, each labelled defensive invariant rather than live path — house style, not exception. Structural alternatives #382 prefers refused below.

**Failing-first evidence.** `packages/core/test/unit/runtime/deferred-publication.test.ts` new; two cases red before change, reasons worth stating, because they make this a behaviour slice not a refactor. Frame case: reads `runtime.tick` after drain publishes, got frame before deferred one. Booking case: counts scheduler's own outstanding jobs across publication, got two for one drain. Neither observable through patch → both survived full quality pass over code containing them, filed rather than seen. Beside them: two deferred frames coalesce to later; deferral naming no frame still publishes through `flush`, deliberately green both sides; throwing `cancel` reported without wedging booking; #388 case disposes runtime inside active publication, asserts through public surface only, as #376's acceptance asked. Pins: in-flight publication finished, no second batch published, `pendingSeeds` empty, runtime still refuses `flush`, no diagnostic reported, job scheduler held gone rather than merely refused when it runs.

`packages/core/test/unit/runtime/graph-runtime-state.test.ts` grows two compile-time cases #387 asks for, reading assignment not property — shape its existing three arrows pass over. Red before brands because assignment they forbid compiles.

**Consequences, two behaviour changes.** No public surface, exported type or member, diagnostic id or rule id retires. Two behaviours move, deliberately, narrowly. Deferred clock publication now advances `#lastTick` when it publishes, previously not at all; `runtime.tick` answers frame asked for, not one before; clock regression guard measured against frame runtime actually reached. Publication consuming drain now cancels job it consumed → scheduler holds one job per drain, not up to two; nothing published twice before, nothing publishes twice now → no batch, patch or sequence moves. One diagnostic message added, under existing `scheduler-failure`, for port refusing to cancel. `#assertTick` added beside `#advanceTick`; `#releaseBooking` added, only caller of `unbookDrain` where three members called it before. `#pendingSeeds` deleted; `#pending` and `#drainHandle` added — one field becomes two, second the port's own handle, not a copy.

**Where reasoning lives.** `graph-runtime.ts` 23,138 → roughly 27,600 bytes, under the 30,000 obliging a sister document; margin stated not assumed — #376 asked for that number, this slice spends part of it. `graph-runtime-state.ts` 7,141 → roughly 11,100. Reasoning that would have pushed source past budget lives here — what this record is for. ADR-082 and ADR-083 deliberately not edited: project supersedes a record with a record rather than amending decided one. ADR-083's "one case worth naming" answered by decision three above; ADR-082's ordering for reentrant clock call preserved, not reversed — frame still not recorded by call that publishes nothing.

**Alternatives refused.** Refusing deferral for clock verb, #380's first: reentrant `flushAtTick` throws, `#flushTick` boundary converts to `flush-failure` diagnostic, seeds dropped not deferred — lost frame number traded for lost work, worse. Declaring dropped frame as contract, #380's third: regression case it owes would pin unobserved behaviour as decision. Growing `#pendingTick` field beside seed set: ADR-076 defect in miniature — "what was deferred" would have two owners; payload one value for same reason memo carries whole key. Making `#flushSeeds` structurally unreachable via `#deferIfFlushing` returning publication continuation, #382's stronger fix: refused — allocates closure per publication on path ADR-083 keeps allocation-free; variant merging both verbs into one private taking optional tick reintroduces at private level shape ADR-082 retired at public one. Threading minted publication permit through `#flushSeeds` considered for same purpose, refused as machinery stating invariant less clearly than assertion. Optional `never` exclusion instead of brand: refused above — deletes diagnostic to add one. Fourth `draining` phase, or return to boolean lifecycle state: still refused, exactly as ADR-083 decision three; #387 explicitly does not disturb it. Fixing any of this inside #386: refused there, correctly, by slice whose whole claim was nothing observable moved.
