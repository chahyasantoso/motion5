# ADR-085: The status file states one Now, and the gate reads its shape rather than its size

**Status:** Accepted, 2026-09-16

**Context.** `docs/SESSION-STATUS.md` is the one document allowed to claim what has landed, and it is also the file every pull request is asked to update. Those two facts made it append-only once already: issue #284 cut it from 99,180 bytes to four sections and gave it a shape gate plus an 8,000-byte ceiling. [Issue #384](https://github.com/chahyasantoso/motion5/issues/384) reports what happened next. The file reached 7,960 bytes, forty of them left, which is less than one markdown link and about half a sentence. Its own gate's comment had already predicted that in words: a status file edited under a budget it can breach in one honest sentence gets edited to satisfy the budget instead of to state the status. [#375](https://github.com/chahyasantoso/motion5/pull/375) wanted to name the follow-up issue carrying the deferred half of #374 and could not afford the link; the count correction it did make spent two of the forty.

The issue's follow-up comment names the defect rather than the symptom, and the file confirms all three parts of it. **Now** held six entries and five of them described merged, closed work, one of them a phase of the project that had already ended. **Next in line** held three, and two of them called [#345](https://github.com/chahyasantoso/motion5/pull/345) and [#339](https://github.com/chahyasantoso/motion5/pull/339) unmerged nine days after both were merged. **Phase** was a seventh entry with a different label, still describing the IK and scroll-source work of two slices ago. So the file was not too large. It was a log wearing a shape gate, and a ceiling cannot say so, because a ceiling cannot tell a current entry from a stale one.

**Decision one. Now and Next in line carry exactly one entry each, and the gate counts them.** A section that may hold one entry cannot accumulate a log at all. That is the property the closed section list already had for headings, applied one level down to the entries inside a section the list allows, which is where every one of the three logs #284 removed actually grew. It also makes the rewrite rule enforceable rather than merely stated: an editor who has to delete the entry in front of them cannot quietly add one beside it, and what they delete is history that already lives in the pull request that landed it.

Exactly one, rather than at most one, and that is deliberate. A project with nothing queued still has to say so in a sentence a reader can check, and an empty section reads the same as a section nobody updated.

Top-level bullets are counted and nested ones are not. The rule is one entry, not one line: an entry that genuinely needs a sub-list is still one entry, and forbidding that would be the budget shaping the writing again, one level further down.

**Decision two. There is no phase bullet.** It was a second Now with a different name and the longest half-life of anything in the file, which is exactly why it was the stalest thing in it. Where the project sits in its plan is [IMPLEMENTATION-PLAN.md](./IMPLEMENTATION-PLAN.md)'s question and it is answered there; what is happening now is the one **Now** entry's, and two owners for one question is the defect this project cares about most. The gate refuses the bullet by its own label rather than trusting that nobody reintroduces it.

**Decision three. The ceiling does not move.** #384 refuses raising it and gives the reason, and lowering it to the rewritten file's size is the same mistake pointed downwards: a ratchet that decides what the status may say. `CEILING` stays at 8,000 and stops being the binding constraint, because the one-entry rule refuses growth on structure before bytes are ever the problem. The ceiling keeps the job it is good at, which is catching a single entry that grows into an essay.

**Decision four. The rule is written where the implementor reads it.** `AGENTS.md` names the one-entry rule, the absent phase, and the thing no gate can check: verify a claim before you write it. Two entries called merged pull requests unmerged for nine days, and nothing automated in this repository could have caught it, because this file is the only place that claim exists.

**Failing-first evidence.** The two cases added to `packages/core/test/unit/scripts/session-status-shape.test.ts` are red before the rewrite, for the honest reason that the file has six entries under **Now**, three under **Next in line**, and a phase bullet above both. The three existing cases are green on both sides: the section list, its order, and the two documents the file hands its departed logs to are all untouched.

**Consequences.** No source, no public surface, no behaviour, no diagnostic and no rule id moves. `docs/SESSION-STATUS.md` loses the phase bullet, five landed **Now** entries and all three **Next in line** entries, two of which were false; it keeps four sections in order, and it states one live area and one queued one. The measured size drops well under the unchanged ceiling, which is the headroom #384 asked for and the reason it is a shape change rather than a trim: the room is a consequence of the rule, not the point of it.

**Alternatives refused.** Trimming the landed narrative and reporting the new byte count, which is what #384's body asks for on its own: refused as a fix that lasts until the next slice, because it corrects the bytes and leaves the mechanism that spent them, and #284 already bought that fix once at ninety-one thousand bytes. Raising `CEILING`: refused by #384, correctly, and its own comment says why. Lowering `CEILING` to the rewritten size: refused above. An expiry policy, where an entry goes stale after some number of days: refused because it needs a clock the gate does not have, and it would let six entries coexist as long as all six were recent. Moving **Now** into `GUARDRAILS.md` or a new document: refused because it moves the file rather than the habit. Enforcing one entry in all four sections: refused, because **Open, and not scheduled** and **Where the rest of it lives** are not per-slice narrative and neither has ever grown.
