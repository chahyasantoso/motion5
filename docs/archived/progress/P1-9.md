## Invariant

`Engine.load()` returns a consumer-facing handle with lifecycle and observation only, and no file under `runtime/` or `graph/` is reachable from the emitted public declaration closure.

## Implementation

`ProjectHandle` exposes `mount`, `unmount`, `seek`, `subscribe`, and `dispose`. `GraphRuntime`, `GraphBinding`, `PatchRegistry`, and `GraphPublisher` stay behind the internal runtime closure, and `Engine` holds `ProjectRuntime` through a structural private helper type so the emitted declaration does not retain the implementation import.

`Patch`, `PatchBatch`, `PatchListener`, and `PatchStatus` moved to `contract/v5`, which is where consumer-facing contracts belong. `runtime/patch-registry` re-exports them, so the registry remains the only writer of a patch without appearing in the public declaration closure.

Consumers that previously reached `runtime.graph.registry.get(...)` now use `subscribe()`. The E2 product-path test was migrated to `subscribe()` plus `seek()`, which is the real consumer shape and a better test than the reach-through it replaced.

## Evidence

The red leg failed on the handle surface assertions and on the emitted declaration scan. The final green run covers quality, integration, boundaries, performance, and formatting.

## Review findings addressed in-branch

1. **The public declaration still exposed graph internals.** `ProjectHandle` imported `Patch` and `PatchListener` from `runtime/patch-registry`, so the emitted `.d.ts` closure reached the registry even though the runtime object no longer did. Contracts moved to `contract/v5`.
2. **The boundary test did not test declarations.** It read source strings from `engine.ts` and `index.ts`. It now emits declarations into a temporary directory, loads the single emitted `index.d.ts`, and walks its import closure; the source check is secondary.
3. **The closure traversal could silently skip imports.** Only `${specifier}.d.ts` was tried and unresolved targets were ignored, so `./runtime/project-runtime.js` would have been skipped rather than rejected: the gate failed open. Resolution now covers extensionless, `.js`, `.mjs`, `.cjs`, `.d.ts`, `.d.mts`, `.d.cts`, and directory `index.d.ts`; unresolved relative imports are collected and asserted **before** the forbidden-path assertion; and the scan requires the traversal to reach more than the entry file. Planted self-tests prove each specifier shape resolves and that an unknown runtime target stays unresolved.

## Known gaps

The declaration scan is a vitest case that shells out to `tsc`, not a required build job. E1 and G-1/G-7 still owe a real per-package build with `outDir`, `exports` pointing at `dist`, and a consumer smoke test importing the built entry from outside the workspace. Until then, this proves the boundary but not publishability.

`GraphRuntime` still exposes `registry` and `binding` to internal callers, and `createHandle` reaches through `runtime.graph.registry` to wire `subscribe`. That is inside the package boundary, but the cleaner shape is `ProjectRuntime` owning a `subscribe` method of its own.
