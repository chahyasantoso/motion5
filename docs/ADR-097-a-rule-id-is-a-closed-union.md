# ADR-097: A rule id is a closed union

- Status: accepted, and implemented on the branch that carries this record. The enumeration exists with a coverage gate, the six generic constructors take `RuleId`, `Diagnostic.ruleId` is typed by it, `Diagnostic` is one flat interface, each rule's severity and its `ids` ownership are stated once in one record in `contract/rule.ts`, and the producers take their `ids` as the argument list that record derives; the record stays intent as to merge, on documentation rule 2 of [README.md](./README.md). The inventory paragraphs below were corrected in place more than once, and the corrections replace the claims rather than being appended beside them; so are the consequences and the follow-up, for that same reason rather than a weaker one. This record has not been accepted onto `main`. It lands with the branch it describes, every slice it records is on that branch, and the superseding convention in [PR-WORKFLOW.md](./PR-WORKFLOW.md) exists so that a reader cannot mistake a retired decision for a current one. A marker naming a sentence written and corrected before either was ever merged would say that one pull request superseded itself, which is the single self-contradicting file that convention's own second exception refuses. The totals they used to state are gone, because the gate is the authority a count kept pretending to be.

## Decision

Rule ids one closed union, `RuleId`, owned by new `packages/core/src/contract/rule-id.ts`; `Diagnostic.ruleId` typed by it.

Prefixed family as template literal type over keyframe rule family, not enumerated twice: prefix real; both halves = one fact in two hand-synced lists. Type applies alias substitution, not separate alias list beside it → `plugin-contribution-stop` derived from `stop-position`, `plugin-contribution-stop-position` unrepresentable; map one owner of aliasing. Family covers every name prefix can apply to, not subset adapter reaches today; over-approximation deliberate: reachable subset measured wrong twice; `plugin-contribution-keyframes-reserved-separator` built in tree, absent from both reachable lists. Family covering every name never fails to type real diagnostic; hand-picked subset fails first time different rule fires.

`ids` ownership per rule, one record; ownership, not arity. `contract/rule.ts` answers two questions per member: severity refused at, whether names ids. Two answers, not three. `"sometimes"` third, exactly two causes, neither survived measurement. `observation-source` reported two refusals under one id → split: shape refusal (source absent, empty, not string → nothing to name) becomes `observation-source-shape`, owns none; qualification refusal keeps id, owns payload always. `live-value-key`, `stale-motion-handle`, `stale-track-handle` minted on thrown error classes, no construction site — absent measurement, not third answer — own none; first site forwarding one into diagnostic with payload fails where decision owed.

Enforcement at producer, not `Diagnostic` shape — correction to first draft. Three ownership-keyed variants declared, paid on public surface: `Diagnostic` exported from package entry. Bought nothing read side: no production reader pattern-matches one; `runtime/patch-registry.ts` compares ids for identity, `runtime/refusal.ts` renders generically. `Diagnostic` one interface; `OwnedIds` at call site, derived from record, refuses payload rule does not own. Diagnostic carrying unowned ids still fails `typecheck`, not ignored; so one omitting ids rule always names. Mechanism argument list, not variant — part first draft misplaced.

`severity` derived from same record via `ruleSeverity`, now only tree expression answering question, not constructor default in place of literal `"error"`. Old default whole bug: rule's answer a suggestion; caller could overrule by passing something else, silently overrode by passing nothing → every warning rule from such caller an error diagnostic nothing noticed. Passing nothing what almost every caller does → correcting default closed it.

Parameter deleted; both corrections recorded in place, not beside. First claimed invariant while only default moved — overclaim status paragraph exists to catch; then said parameter survives, true then, not now. Nineteen sites named severity, every one named severity its rule already fixes → no diagnostic moved when parameter went; compiler enumerating those sites what deletion owed, not fourth hand count. `contract/validate-v5.ts` forwards rule id, path, message; local helper carries no `= "error"` default; `adapters/trigger-factory/default.ts` names no severity. No argument position left to name one → invariant reader might have taken it for, stated only now true.

Fixed pair promised withdrawn; measurement why. Arity not checkable where diagnostic built: every `ids` arrives via `Object.freeze([...])`, widens two-element literal to `readonly string[]` before any type sees it → `readonly [string, string]` field would refuse code already constructing correctly. Arity not single-valued: `observation-source` one id at one site, none at another; `plugin-unknown-key` one at three sites, two at fourth; `plugin-contribution-shape` one at one site, two at another. Group per arity would declare wrong one for three rules to keep build green — per-rule lie one level down. Ownership part both true and enforced, only part type states; arities in inventory coverage case measures, not declaration.

Generic constructors narrowed same time; six, not five. `contract/diagnostics.ts` `diagnostic`, `graph/ir.ts` `diag`, `runtime/report.ts` `frozenDiagnostic`, `domain/keyframe-compiler.ts` `diagnostic`, plugin `diagnostic`, `graph-runtime.ts` `#report` all took `string`; closed union whose only producer accepts `string` closed nowhere. All six take `RuleId`; five non-constructor forward to it, not building frozen shape → shape one owner, severity one answer. `frozenDiagnostic` attributed to `contract/diagnostics.ts` by first inventory; lives in `runtime/report.ts`, which declares `diagnostic`, not `frozenDiagnostic`. Narrowing is slice, not follow-up.

Ten refusal prefixes stay. Already closed union in `refusal.ts`, two total switches; pulling into `RuleId` gives one namespace two owners, makes `describeRefusal` depend on contract layer for string it templates itself.

Enumeration gets gate, on rule evidence-id gate earned in issue #283: where gate reads hand-maintained subject list, case asserts list covers subjects actually present. Literal-only scan answers absent for entire prefixed family → case asserts it found prefix site too. Asserts coverage, never total: inventory wrong twice; number would pin error.

## Alternatives considered

Branded nominal type over `string`. Rejected: closes assignment, not enumeration → nothing can switch on it; acceptance criterion asking one type listing every id unmet.

Prefixed family as 22 more literals beside base ones. Rejected on DRY rule project applies to derived facts: prefix derived from base name at run time → deriving in type too one owner; two hand-maintained lists shape issue #283 refused.

Tuple per rule for `ids`, as issue sketches. Rejected, unavailable: `graph-cycle`, `ik-target-not-single-leaf` no fixed arity; false pin refuses real diagnostic or forces cast at build site.

Splitting `Diagnostic` into one interface per severity. Rejected: severity not question any reader asks; ADR-016 keeps runtime diagnostics inline on one channel.

## Consequences

Adding a rule breaks build at `rule-id.ts`, where id named, not inherited silently by every consumer pattern-matching a string. Acceptance criterion issue asks for.

Touches `contract/v5`; `Diagnostic` exported from package entry → consumer constructing `Diagnostic` with own rule id stops compiling. Public surface change, owes version decision in slice that lands it, not here.

Alias map in `validate-v5.ts` stops being free data, becomes typed mapping. Cost of prefix in type; only place paid.

`ids` ownership enforced at producer; boundary stated, not implied. Diagnostic checked at call site building it, against rule's owned argument list. No variant to check against, no narrowing for assertion: `Diagnostic` flat → `asDiagnostic` a widening, not correlation stated once; "boundary stated rather than implied" stopped describing a union; widening deleted with last raw producer it survived for. `DiagnosticFields` went too. Hole closed, not merely bounded: nothing names a rule by literal and hands over unowned payload — no expression accepts the two independently. Invariant over every construction, not assertion boundary, stated only now every construction goes through one call. Producer takes `ids` as `OwnedIds` of rule id handed → ids-free rule cannot pass one, always-ids rule cannot omit. Derivation guarded by one-element tuple each side of `extends`: naked conditional distributes over `RuleId`, answers union of both lists — every caller broken, not one boundary open. Two ownership answers → no third list; optional case only where compiler cannot prove every member of `Rule` shares one answer: open `RuleId`, or union spanning both, where neither guarded `extends` succeeds. Limit, not bug, stated because deleted record stated it, reader would not suspect: correlates one rule id, not set. No call site holds such union. Two producers forward rule id held as data, not literal; neither open now. `contract/validate-v5.ts` reaches constructor via `scopedRuleId`, return narrowed to `KeyframeRuleId | ContributionRuleId`; both families own no ids → derived list empty, forwarding call checked against it, not accepted by claimless branch. `runtime/report.ts` via private `frozenDiagnostic`, reached only from exported member deriving own list. First compiler-backed, second backed by record in `contract/rule.ts`.
