# ADR-079: One publication owner, and a return value that means one thing

**Status:** Accepted, 2026-09-14

**Context.** [Issue #369](https://github.com/chahyasantoso/motion5/issues/369) collected findings deferred from review of [#368](https://github.com/chahyasantoso/motion5/pull/368), the value-tier batch. None incorrect at reviewed head; all commentary on design review otherwise endorsed, why left out of pull request already fixing red CI. Recorded together: four of six one question asked from four directions — who owns a publication.

Reviewed head had three copies of same two statements: invalidate seed list on graph, then record diagnostics returned batch carries. `#flush` had them, `#invalidateOne` had them, public `invalidate` had them. ADR-078 examined first two, decided keep apart; did not examine third, left standing by reasoning inherited from second. Reviewed head also had one member answering value meaning two different things, and a rung whose name described opposite of what it did.

**Decision.** Four things; first reverses decision ADR-078 made three weeks of commits ago, not quietly diverging from it.

**One: `#invalidateSeeds(nodeIds)` is the one place a seed list becomes a published, recorded batch.** `#flush`, `#invalidateOne`, public `invalidate` all end there. Each keeps own preconditions and failure contract — precisely what ADR-071 refused to merge, not what this does: ADR-071's objection was combining `#flush` and `#invalidateOne` gives one member context-dependent contract; here contracts stay in members owning them, only mechanics move down.

ADR-078 refused this exact spelling: `LV-5` and `PK-17` read `#invalidateOne`'s declaration, assert two statements inside it, so moving them turns two green cases red for no behavioural reason. Remeasured: `PK-17` reads `#writeValues(`, for `if (involved)` and `validateTrackDefinition(rewritten`; its subject malformed stop list refused before anything mutates. One case reads `#invalidateOne`, not two. Three test files read regions of this source at all; none addresses public `invalidate`. Price one re-addressed case, not two; thing bought larger than ADR-078 could see, third copy not found yet. Two copies of two statements tidy-up; three copies of one question is defect this project cares about most.

What four records naming `#invalidateOne` name unchanged. Still value tier's single-node flush; still asserts runtime liveness so disposed project reported by owner that decided, not layer that noticed; still answers actual batch. Identity never two statements underneath those facts. `LV-5` re-addressed, not weakened; strictly stronger now: asserts exactly one member in whole file names graph call at all — claim previous form could not make, second copy anywhere else would have satisfied.

**Two: `#flush` answers nothing, and the empty-seed decision gets its own owner.** Returned `undefined` both for disposed runtime and empty seed list; `values` collapsed two into empty batch with `??`. Nothing wrong at that head: `#assertLive()` ran immediately before it at every call site. Safety by statement ordering; next call site not written in that order is where it stops holding. So `#flush` keeps one decision — disposed runtime skipped, not reported — returns `void` as before batch; `#publishSeeds(seeds)` owns what empty list means, is what `values` publishes through and `#flush` delegates to, so empty-seed rule still exactly one owner. `#publishSeeds` asserts liveness itself, making answer unambiguous by construction: every batch it hands back is one it published or one with nothing to publish. `values` keeps own re-ask after recipe: that answers issue #288's question, not this one; two side-effect-free field reads cannot disagree.

General form, reason this is record not diff: sentinel collapsing two conditions deleted, not documented. Two owners cost one member here; comment saying which of two an `undefined` meant costs reader every time.

**Three: public `invalidate` is not folded into `#flush`.** Follow-up asked whether it could be, since no test reads its declaration way one reads `#invalidateOne`'s. Coupling genuinely absent; answer still no, for stronger reason than exemption. `invalidate([])` publishes today, answers batch that publication produced; `#flush` skips empty list, so folding silently changes public answer. Also makes public verb's return optional — hands callers second failure contract to narrow rather than removing duplicate. Duplication those two members shared was mechanics; decision one takes it.

**Four: `#refuseValueReentrant` becomes `#refuseImmediateReentrant`.** Old name read as refusal of value-verb reentrancy — opposite of job: pair of conditions value verb must pass to be allowed to join batch. Both about immediate family every verb in this class belongs to — vocabulary `immediateInTransaction` and immediate-verb refusal cases already use — leaves `#refuseReentrant` defensible as total rung adding batch condition. Five call sites, no behaviour, no diagnostic, no rule id.

**Also decided, and small.** `#teardown` clears `#valueSeeds` beside `#open`: both open transaction state; that member claims concept; relying on `values`'s own `finally` to finish half its stated job made claim half true, not harmless. Both value-batch factories drop `as PatchBatch` for annotated local: two functions whose entire job is producing correctly shaped batch had opted out of check that they do it; review's open question answered by looking — `PatchBatch` four readonly members, frozen literal satisfies it unaided. And `RA-170` drives `setKeyframe` through `#recompileKeyframes` inside batch, which review traced by hand and no run had ever executed, even though it is call `apps/ik-playground/src/scroll-reach.ts` makes. **Refined by [ADR-094](./ADR-094-one-closed-value-per-runtime-decision.md), 2026-09-18.** Sentence about both value-batch factories names functions tree no longer has: `value-batch.ts` deleted; `batchFor` in `report.ts` is one builder of four-field batch three modules used to build, so what sentence decided about two functions now has one place to hold. Decision stands; only spelling moved.

**Consequences.** One member gains publication mechanics; three lose copy of them. `#flush` loses return type, which its three settlement callers already ignored. Seven private members own seven questions where five owned seven. No public surface moves: nothing added, removed or renamed on exported type or member; no refusal set changes; every diagnostic and rule id untouched — why this ships as fix, not tier.

This record amends ADR-078's first decision, not editing it; leaves ADR-069, ADR-070 and ADR-071 standing, each names `#invalidateOne` for property this change preserves. Reader arriving at ADR-078's `#invalidateSeeds` refusal should read it as accurate about tree it measured, superseded by measurement above.

**Alternatives refused.** Renaming `#invalidateOne` to shared owner, deleting single-node member: it has caller-facing report contract `#flush` must not have; four records name it. Giving `#flush` discriminated result so two conditions stayed distinguishable inside one member: two-meanings defect with more syntax; caller still branches on condition it cannot cause. Keeping casts, asserting batch shape in test instead: compiler already answers that question; test re-answering it second owner of a check.
