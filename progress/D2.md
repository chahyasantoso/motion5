## Scanner gap this slice closes

The parent walked the five core layers and then hardcoded exactly one extra file, `engine.ts`. `packages/core/src/index.ts` was only inspected for allow-listed export names and `packages/core/src/internal.ts` was never read at all, so either public entry could import a renderer or carry banned compatibility vocabulary while the boundaries job stayed green. `scanCoreEntries` now reads every file directly under `packages/core/src` in sorted order. Nested `adapters/` stays out on purpose: the DOM and GSAP adapters exist to touch those boundaries.

Without this change D2 would have shipped no source at all, and its failing-first evidence would have been a green-on-base placeholder.

## Deliberate non-rule

Consumer packages are **not** scanned with `importsBoundary`, `importsRenderer`, or `bannedSymbol`. `packages/react` imports React because that is its job, and a renderer rule aimed at core layers would make the shipped tree permanently red. The planted `packages/vue/src/index.ts` imports React on purpose and the test asserts that no renderer violation is reported for it. Core layers and core package entries keep the full rule set.
