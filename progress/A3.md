# A3: guard subscriber-triggered reentrancy

Slice branch: `fix/A3-publisher-reentrancy` (from the `rescue/restore-motionpath-parity` tip
[`1230dc81`](https://github.com/chahyasantoso/motion5/commit/1230dc819d0e17337bd0820935f9a832de0f8d5b)).

Status in [`STATUS.md`](STATUS.md) is authoritative. This file is evidence only.

## Invariant

A flush requested while patch subscribers are being notified never runs inside that flush: it
is coalesced into exactly one follow-up invalidation that the next flush drains.

## The defect

`PatchRegistry.closeBatch()` clears `#batchOpen` before notifying listeners so that listener
failures cannot leave the batch open (A2). That correct fix left the notification window
unguarded: a subscriber could call back into `GraphRuntime.invalidate()`, open a second batch,
and publish from inside the first notification. Consequences observed by the failing-first
test on the parent commit:

- the nested batch reached batch listeners **before** the batch that triggered it;
- `#lastTick` advanced inside another flush, so the next real clock tick failed the strictly
  increasing check with `RangeError`;
- nothing named the behavior, so "the follow-up ran" and "the follow-up was lost" were
  indistinguishable.

## Chosen policy

One policy, three owners, no second clock:

1. **`PatchRegistry`** owns the notification window. `notifying` is true only while a settled
   batch is being delivered, and `beginBatch()` refuses to open during it
   (`REENTRANT_BATCH_MESSAGE`). The window closes in a `finally`, so the registry is reusable
   even when a listener throws (A2 stays intact).
2. **`GraphPublisher`** fails fast at the same boundary before touching batch state. Traversal
   is not a scheduler and holds no queueing policy.
3. **`GraphRuntime`** owns the policy. While flushing, a further `flush()`/`invalidate()` adds
   its seeds to one pending set and returns an empty batch carrying a
   `reentrant-flush-deferred` warning diagnostic. The next flush (normally the next clock
   tick) unions the pending seeds into its own seeds and clears them, so the follow-up runs
   once. If that flush throws, the carried seeds are restored.

`ProjectRuntime.seek()` inherits this for free: it delegates to `GraphRuntime.invalidate()`.

## Motionpath oracle

motionpath's scheduler drives progress from one ticker and treats a change raised during
notification as work for the next frame rather than a nested traversal. That timing behavior
is what is ported. Not copied: motionpath's `GraphPublisher.js` traversal, its Track-owned
graph walk, and any additional RAF/ticker ownership.

## Motion5 boundary

Unchanged owners: `GraphBinding` transactions, publisher traversal/failure containment, the
single clock subscription in `GraphRuntime`, and the A1 final-value memo. No new public
export: `notifying` and `pendingSeeds` are runtime-internal reads.

## Deletions

None. No placeholder or duplicate owner existed for this behavior; the gap was a missing
guard.

| Assertion | Parent behavior |
|---|---|
| batch listener order is `[1]` after one tick | `[2, 1]`: nested batch delivered first |
| `runtime.tick === 1` after one tick | `2`: reentrant call advanced the tick |
| deferred batch carries `reentrant-flush-deferred` | no such batch; a real publication is returned |
| `runtime.pendingSeeds` queues the follow-up | member does not exist |
| second `clock.tick()` still delivers tick `2` | `RangeError`: clock tick no longer strictly increasing |
| `beginBatch()` inside a subscriber throws | opens a nested batch silently |
| `publisher.flush()` inside a subscriber throws | nests a full publication |
