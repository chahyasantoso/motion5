# P0-3b: authored-duration pinning

- Status: Red expected, test-only commit pushed
- Branch: `fix/P0-3b-authored-duration-pinning`
- Parent commit: [`8e93de4e`](https://github.com/chahyasantoso/motion5/commit/8e93de4ea1a448aaaade35ce95e7c47d0cfbe9a3)

## Invariant

A compiled timeline's real duration is the authored track duration, whatever the authored stops do at the tail, so `progress(v)` always means the same authored position.

## The defect

GSAP computes a timeline's own duration as the latest scheduled child's end time. Nothing pins that to the authored duration. When the last authored stop sits before `p = 1`, the real timeline is short, and two things follow:

1. **Every authored position is rescaled** by `1 / lastStopPosition`, not just the tail. With `stops: [{ p: 0, v: 0 }, { p: 0.5, v: 100 }]` the timeline is `0.5` long, so `progress(0.9)` is read as 90% of `0.5`, lands at local time `0.45`, and returns `90` instead of the held `100`.
2. **The public contract lies.** `InterpolationTimeline.duration` forwards `timeline.duration()`, so a consumer reading the authored duration gets the short number.

This was found while reviewing P0-3 and is deliberately scoped as its own slice: P0-3's two named sub-bugs (cross-property collision, leading hold as delta) are genuinely closed, and this is a third, independent defect in the same compiler.

## Why the existing suite cannot see it

`gsap-absolute-stops.test.ts` uses a deterministic double whose `duration()` is a hardcoded `() => 1`, which is precisely the value under test. Every other authored fixture in the repo ends its last stop at `p = 1`, the one shape where the real duration happens to be correct. Same class of camouflage as P0-2 and P0-3: the fixture supplies the answer the adapter is supposed to produce.

## Owner

The GSAP interpolator adapter. Nothing outside `packages/core/src/adapters/interpolator/gsap.ts` changes: no graph ownership change, no port change, no second clock, and `Track` still only reads `state`.

## Motionpath oracle

The oracle emits a single `gsap.to(proxy, { keyframes, duration, paused: true })` with an explicit `duration`, so its timeline is authored-length by construction and the defect cannot arise. motion5 schedules one tween per authored interval instead, which is what makes the tail explicit rather than implied, so the authored end has to be scheduled rather than inherited.
