## Invariant

A compiled timeline's real duration is the authored track duration, whatever the authored stops do at the tail, so `progress(v)` always means the same authored position.

## The defect

GSAP computes a timeline's own duration as the latest scheduled child's end time. Nothing pins that to the authored duration. When the last authored stop sits before `p = 1`, the real timeline is short, and two things follow:

1. **Every authored position is rescaled** by `1 / lastStopPosition`, not just the tail. With `stops: [{ p: 0, v: 0 }, { p: 0.5, v: 100 }]` the timeline is `0.5` long, so `progress(0.9)` is read as 90% of `0.5`, lands at local time `0.45`, and returns `90` instead of the held `100`.
2. **The public contract lies.** `InterpolationTimeline.duration` forwards `timeline.duration()`, so a consumer reading the authored duration gets the short number.

This was found while reviewing P0-3 and is deliberately scoped as its own slice: P0-3's two named sub-bugs (cross-property collision, leading hold as delta) are genuinely closed, and this is a third, independent defect in the same compiler.

## Why the existing suite cannot see it

`gsap-absolute-stops.test.ts` uses a deterministic double whose `duration()` is a hardcoded `() => 1`, which is precisely the value under test. Every other authored fixture in the repo ends its last stop at `p = 1`, the one shape where the real duration happens to be correct. Same class of camouflage as P0-2 and P0-3: the fixture supplies the answer the adapter is supposed to produce.

## Implementation

Compilation now reports `end`, the latest authored stop position across every property, read from the authored `p` directly so it carries no accumulated rounding. When `end` lands before the authored end, the adapter schedules a single zero-length tween at the authored end position.

The pin targets an adapter-owned anchor object, never the published proxy. A key added to the proxy would flow through `Track.compose` into a published patch and reach the renderer as a value nobody authored. It is also conditional: a grid that already reaches `p = 1` gets no extra tween, which the tween-count assertion holds in place.

An `end` beyond `1` is left alone. Authored positions outside `[0, 1]` are a validation concern (P1-10), and trimming them here would hide the authored mistake.

## The one repair in between, and what it was

The implementation commit left exactly one failure: `expected [ 'x', '_gsap' ] to deeply equal [ 'x' ]`.

That was the test being wrong about real GSAP, not the fix being wrong. GSAP stamps its own `_gsap` cache onto every target it animates, so the proxy carries that key from the property tween itself, with or without pinning. The assertion was failing on a key the fix did not add.

[`6719d408`](https://github.com/chahyasantoso/motion5/commit/6719d408c705a26a2ca28bd88c6a91dccd85bd61) repairs the oracle instead of relaxing the claim. It compares the authored surface, which is what `rendererNeutralState` publishes after stripping underscore-prefixed keys, asserts it on both the pinned and unpinned timelines so pinning is proven to add nothing, and names the anchor key directly: `authoredEnd` has no underscore, so if the pin ever targeted the proxy the filtered comparison still catches it. The invariant is unchanged and the assertion is now strictly stronger than the version that failed.

This is the same distinction P0-3 had to make: repairing a test's model of the world is legitimate, weakening its assertion is not.

## Owner

The GSAP interpolator adapter. Nothing outside `packages/core/src/adapters/interpolator/gsap.ts` changed: no graph ownership change, no port change, no second clock, and `Track` still only reads `state`.

## Motionpath oracle

The oracle emits a single `gsap.to(proxy, { keyframes, duration, paused: true })` with an explicit `duration`, so its timeline is authored-length by construction and the defect cannot arise. motion5 schedules one tween per authored interval instead, which is what makes the tail explicit rather than implied, so the authored end has to be scheduled rather than inherited.

## Deletions

None. This slice adds a scheduled authored end; it removes no owner and no API.

This is a small instance of the review's G-4 finding: a gate that reads a checkout rather than an assertion cannot tell those two states apart.
