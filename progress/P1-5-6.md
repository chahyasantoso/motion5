## Invariant

A patch is republished only when its content actually changed, and a settled batch is delivered to exactly the listeners that existed when it settled.

## Implementation

`PatchRegistry` now compares `values` and `sourceRevisions` with `domain/values.ts#equalValues`, the single structural compare in the codebase, and compares diagnostics field by field instead of stringifying both sides. `closeBatch()` snapshots node listeners into arrays, matching what batch listeners already did, so subscribing or unsubscribing inside a listener takes effect on the next batch instead of mutating the collection being walked.

## Evidence

- Red leg: the test-only commit failed on the parent, and only the quality job failed. Integration and boundaries passed on the same checkout, so the red was assertion-level rather than an import, typecheck, or config failure.
- What failed: structurally equal nested records republished and bumped the revision, diagnostics that differed only in key order counted as a change, a node listener released by an earlier listener was skipped, and a node listener added during notification received the already-settled batch.
- Negative cases are asserted too (real nested change, nested array reorder, source-revision change, changed diagnostic field), so an always-equal compare cannot pass the gate.
- Green leg: all behavioral jobs pass on the implementation commit, and again on the formatting child commit.
- This evidence commit is verified by its own CI run, linked in the pull request thread.

## Known gaps

Per-flush allocation is still O(graph) rather than O(dirty); the publisher continues to rebuild dependents and compose wrappers on every flush, and `freezeValue` still re-walks the value tree per plugin. Those are the separate P2 precompute items, not this slice.
