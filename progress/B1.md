# B1: prepare-stage plugin contribution

Branch: `fix/B1-track-contribution`, from rescue commit [`bec08ded`](https://github.com/chahyasantoso/motion5/commit/bec08ded24da9b5febdca19be81be6edd84cea53).

## Invariant

A plugin with `stage: "prepare"` contributes to the interpolation config once during Track construction, before the adapter timeline is created. `Track.compose()` must never rerun preparation.

## Failing-first evidence

Red test commit: [`9f2390f9`](https://github.com/chahyasantoso/motion5/commit/9f2390f9a1ce992f35c938ccf7526ba08e51c085), [test](../packages/core/test/unit/domain/track-contribution.test.ts).

The test expects a prepare plugin returning `{ y: 2 }` to merge into `{ keyframes: { x: 1 } }` before `interpolator.create()` receives the config, and expects `contribute()` to run once even after two composes. The parent Track passes the raw config and never calls `contribute()`, so this is red by construction.

## Owner

`Track` owns the one-time preparation boundary. The plugin registry only resolves and orders plugins; the interpolator owns the resulting timeline.

None yet.

`npm run check`, plus the focused Track test, on the implementation commit.
