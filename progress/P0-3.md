## Invariant

Authored stop positions are absolute normalized timeline positions. Each property keeps its own stop grid, easing, leading hold, and trailing interval. One property's stops must not overwrite another property's timing.

## Failing-first evidence

Test: [`packages/core/test/contract/gsap-absolute-stops.test.ts`](../packages/core/test/contract/gsap-absolute-stops.test.ts).

The first test version correctly caught the implementation bug, but its deterministic timeline double incorrectly let a later chained tween overwrite the completed value at an exact boundary. CI [run #31616782139](https://github.com/chahyasantoso/motion5/actions/runs/31616782139) exposed that model defect at `p=0.25`: expected `{x:25,y:25}`, received `{x:25,y:20}`. The assertion was never weakened. Commit [`92f9f8b2`](https://github.com/chahyasantoso/motion5/commit/92f9f8b2a14f099ca258a2b573d34d4fba64f262) repaired only the fake timeline's chained-segment semantics, by selecting the active segment per property and using the prior segment's endpoint as its start value.

That was the right kind of red: the test oracle was repaired, not the assertion.

## Implementation

`compileKeyframes()` now emits one segment per authored interval with:

- property key and endpoint value;
- absolute normalized start position;
- independent interval duration;
- authored easing metadata.

The adapter scales both start and duration by the track duration and passes the position to the single paused GSAP timeline. This preserves leading holds and prevents cross-property ordinal timing corruption.

This is a different mechanism from the one the post-E3 review suggested. The review proposed a single shared percent-keyframe map; this uses GSAP's absolute position argument on `.to(target, vars, position)`, one tween per authored interval. Both satisfy the invariant, and the real-GSAP test below is what proves the equivalence rather than asserting it.

## Oracle and boundary

The reference is motionpath's percent-keyframe behavior and its per-property authored intervals. The implementation stays inside motion5's adapter boundary: proxy state remains adapter-owned, Track still reads `state`, and the project still owns the only clock.

## Real-edge evidence, and why the earlier green was not enough

Commit [`6a0bdb7`](https://github.com/chahyasantoso/motion5/commit/6a0bdb7dcdad9a51792105c5546e21a845d4961d) closes a hole that the passing suite could not see.

Both real-GSAP wrappers in the repo declared `to(target, vars)` and dropped the absolute position argument. TypeScript accepts the narrower function structurally, so on the real library every segment still sequential-appended: exactly the defect this slice exists to fix. The only test exercising positions was a hand-rolled deterministic double, so P0-3 had **no real-GSAP evidence at all**, and the suite could not have gone red even with the implementation reverted.

The fix is one pass-through seam, [`packages/core/test/support/real-gsap.ts`](../packages/core/test/support/real-gsap.ts), which forwards the timeline config and every tween position verbatim and exposes real GSAP's own `paused()` and `duration()`. It observes and never corrects. Both hand-rolled wrappers are deleted.

This also closes the outstanding half of P0-2. `createRealGsapInterpolator` hardcoded `gsap.timeline({ paused: true })` inside `end-to-end.test.ts`, which is the camouflage the review asked to remove; it survived the P0-2 merge and is now gone. `paused()` is asserted through real GSAP in both the contract test and the E2 product path, alongside the existing config-level assertion: one proves what the adapter asked for, the other proves what GSAP did with it.

## Follow-ups this slice deliberately does not cover

- **Authored-duration pinning.** GSAP computes a timeline's own duration as the latest scheduled child end-time, and nothing pins it to the authored duration. Any final stop with `p < 1` therefore rescales the entire progress mapping by `1 / lastStopPosition` and shortens the public `InterpolationTimeline.duration`. The suite cannot see it because the deterministic double hardcodes `duration: () => 1`. Tracked as P0-3b.
- **P1-10.** `readStops` still silently filters malformed stops instead of diagnosing them, so out-of-range positions still animate something arbitrary.
