Status: not implemented. Depends on: B7, C4, D4, G2, G3.

Read `00-overview.md`, `cache-contract.md` sections 6, 8 and 9, D4's adapter and whole-solve memo helper, `packages/plugins/src/ik3d.ts`, `ik3d-chain.ts`, `ik3d-solve.ts`, `ik3d-fabrik.ts`, `ik3d-analytic.ts`, `ik3d-constraint.ts`, `ik3d-orient.ts`, `ik3d-seed.ts`, `ik3d-serial-recovery.ts`, `ik3d-result.ts`, and ADR-118, ADR-120, ADR-122, ADR-123, ADR-124 and ADR-129 to ADR-132. ## Outcome and work

`ik3d` keeps its name and gets the new contract:

- Slots: a required `skeleton` slot declaring `capability: ["chain3d", "joined3d"]`, a required nonempty `targets` dict, and an optional scalar `pole` slot. The pole, like every goal, is a runtime frame value read through `readFrame3d`, not a structural capability. There is no `root` slot, no singular `target` slot, no `solverChain` and no `members` input.
- Outputs: it folds `rotations3d` and opt-in `inspection` (ADR-120). Options stay local unless declared outputs.
- `ik3d.validate` applies C4's rules through the space-neutral rule ids: at least one non-root solve member (`ik-solver-no-solve-members`), exactly one target per non-root leaf, and refusal of unknown, topology-root or non-leaf goal IDs. Retain ADR-118's pole semantics; any structural precondition it states (for example the chain shape a pole applies to) becomes an `ik3d.validate` refusal, not a runtime fallback.

Adapter: compose the first point's tip once from the source's root frame and anchor it; it is not a solve member. Adapt non-root members parent-first with stable point IDs, pivot offsets, extents, rest orientations and compiled parent links, and read joint limits, influence and orient from the point records G2 defined. Feed the retained FABRIK tree, analytic, constraint, orientation, seed and serial-recovery code unchanged in meaning. No topology discovery, graph access or cache dependency in the mathematics.

Memo: build one frozen canonical 3D SolveRequest from exactly what the solver consumes, including anchored tip, ordered members and parent links, pivots, extents, rest orientations, constraint variants, influences, orient weights, goals, pole, and every consumed option, policy and seed. Use D4's whole-solve memo helper (capacity-one table, hit/miss union read exhaustively) without copying it. Memoize the whole validated result including quality data; project inspection after lookup.

The new plugin owns its slot and key names (`pole`, `inspect`, `inspection`, `rotations3d`) in the plugins package. Stop importing `POLE_SLOT`, `INSPECT_KEY` and `INSPECTION_KEY` from `@motion5/core/plugin-api`; those core constants (`contract/solver-shape.ts`, `contract/solver-constraints.ts`) belong to the quarantined kinematic channel that F2 deletes.

Delete the compose `ik3d` and its C7 parity test. Rewrite the executed examples in `docs/guide/inverse-kinematics-3d.md` (run by `packages/plugins/test/integration/ik3d-guide-examples.test.ts`) to the new contract in this slice; F3 owns the surrounding prose.

## Evidence and finish

Run the retained 3D suites through the adapter (`ik3d-joint`, `ik3d-orient`, `ik3d-tree`, `ik3d-envelope`, analytic, constraint, seed and offsets tests): reachable/unreachable, trees, limits, pole, influence, orientation, inspection off/on. Run default, no-cache and evicting providers; mutate each consumed request field independently and require a miss; equal effective requests in fresh records hit. Cover absent pole versus bound blocked/error pole, goal and pole rebinding to equal numbers (cold generation), malformed runtime goal frames, late downstream failure and retry.

Done when `ik3d` consumes only its declared skeleton, targets and pole, solves with the retained mathematics and memoizes complete effective requests through the shared helper. Record the key audit, commands/results and limits. Next: G5.
