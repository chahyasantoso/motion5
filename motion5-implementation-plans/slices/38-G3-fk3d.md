# G3 — Rebuild fk3d as stateful cached FK over a 3D skeleton

Status: not implemented. Depends on: B7, C7, D3, D5, G2.

## Start here

Read `00-overview.md`, `cache-contract.md` sections 6–7 and 9, D3's uncached reference, D5's generic cached walk helper, `packages/plugins/src/fk3d.ts`, `packages/plugins/src/frame3d.ts` (`composeWorld3d`, `pivotFromBase3d`, `blendOrientation3d`), `packages/plugins/test/support/fk3d-compose.ts`, ADR-116 and ADR-117. Do not add a second cache implementation or transaction path.

## Outcome and work

`fk3d` keeps its name and gets the new contract. It is a stateful plugin (`defineStatefulPlugin<S, P>`) with a required `skeleton` slot declaring `capability: ["chain3d", "joined3d"]` and an optional scalar `solver` slot. It has no `base` slot and no per-bone entry: one `fk3d` entry poses a whole 3D skeleton. It folds `poses`, a record keyed by point ID whose values are 3D TIP frames `{ x, y, z, rotation, rotationX, rotationY }`.

Composition per point, parent-first over the resolved layout: the parent tip is the source's root frame for the first point and the parent point's tip otherwise; apply the pivot offset in the parent frame (ADR-117), then the blended orientation, then the nonnegative extension along local +x. Blend the authored rest orientation with the solved orientation by `weight` through `blendOrientation3d` (ADR-116). A missing solved orientation uses the rest orientation. A zero-length point publishes the joint frame itself, which is what G7's captured skeletons rely on.

Solver contract: the solver is a `rotations3d` producer. Built-in `ik3d` must bind the same skeleton source/layout/root provenance (C4's rule, applied to 3D); custom producers declare compatible provenance, partial maps are valid, unknown or non-finite orientations refuse. An absent optional solver differs from a bound blocked/error/malformed one.

Caching: use D5's generic cached walk with a 3D composer from `frame3d.ts`, a 3D effective-key normalizer and exact frame equality (Object.is on all six fields, signed zero preserved). The key holds the exact effective values the composer consumes: parent tip, pivot offset, extent and blended orientation. Do not key on raw authored bags, weight alone or solver-record identity. One table slot per compiled point, one remember batch per evaluation, exact-equal recomposition retains the old frame.

Promote `packages/plugins/test/support/fk3d-compose.ts` (or a successor) to the uncached 3D reference, the counterpart of D3. It must not import the cache helper.

Delete the per-bone compose `fk3d` with its `base`/`solver` slots and its six scalar world outputs, and delete its C7 parity test. Classify the old `fk3d` tests by invariant: geometry, pivot-offset and rest-orientation assertions are rewritten against the new plugin; per-bone wiring assertions are removed with that reason.

## Evidence and finish

Compare default, no-cache and evicting providers with the uncached 3D reference across chains and joined trees, translated/rotated roots, nonzero 3D pivots, zero/negative extents, weight endpoints, partial custom solves, full animation and seek histories. Count compositions: identical effective inputs add zero, a leaf-only edit adds one in an uncoupled fixture. Test key-field perturbation per field, signed zero, solver provenance mismatch, same point IDs in two skeletons, late failure/retry and once-per-generation disposal.

Done when one `fk3d` entry poses a whole 3D skeleton through the shared cached walk with geometry equal to the uncached reference. Record commands/results, call counts and reference guarantees. Next: G4.
